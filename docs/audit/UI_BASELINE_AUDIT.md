# UI BASELINE AUDIT — DailyOPIc (iOS)

> 최초 작성: 2026-08-07
> **개정: 2026-08-07 (2차) — 시뮬레이터 전면 탐색 후 재작성**
> 성격: **READ-ONLY 현황 조사**. 이 문서 외 어떤 코드/설정/외부 리소스도 변경하지 않았다.
> 대상: `DailyOPIc/` (SwiftUI, iOS 17.0+)

## 이 개정판이 1차와 다른 점

1차 audit은 **Firebase App Check 403으로 인증 단계에서 막혀** 3개 화면(Splash / ATT / AuthRecovery)만 `[SIM]`이었고, 나머지는 전부 `[CODE]` 추론이었다. 또 "UI 자동화 도구 미활성"을 제약으로 기록했다.

**두 제약 모두 해소됐다.**

- App Check 디버그 토큰이 Firebase 콘솔에 등록되어 익명 인증이 통과한다 → 앱 본체 전 화면 도달 가능
- `tap` / `swipe` / `snapshot_ui` / `screenshot` UI 자동화가 동작한다 → 실제 조작 기반 탐색 가능

그 결과 **1차의 `[CODE]` 다수가 `[SIM]`으로 승격**되었고, **코드만 봐서는 보이지 않던 P0급 결함 3건이 새로 발견**되었으며, **1차에서 문제로 적었으나 실제로는 문제가 아닌 항목 2건을 철회**한다. 변경 내역은 §11에 전부 명시했다.

## 증거 표기 규칙

| 태그 | 의미 |
|------|------|
| `[SIM]` | **SIMULATOR VERIFIED** — 실제 시뮬레이터에서 눈으로 확인함 |
| `[CODE]` | **CODE VERIFIED** — 소스에서 확인했으나 시뮬레이터로 재현/관찰하지 못함 |
| `[UNVERIFIED]` | 코드로도 시뮬레이터로도 확정하지 못함 |

`[CODE]`는 "구현이 이렇게 되어 있다"는 사실만 보장한다. 실제 렌더링 결과·타이밍·체감은 보장하지 않는다.
`[SIM] + [CODE]`는 **현상을 시뮬레이터에서 관찰하고 원인을 코드에서 확정**했다는 뜻이다. 이번 개정에서 가장 신뢰도 높은 등급이다.

## 1. 현재 빌드 / 실행 상태

### 1.1 빌드 `[SIM]`

| 항목 | 값 |
|------|-----|
| 프로젝트 | `DailyOPIc/DailyOPIc.xcodeproj` (workspace 없음) |
| Scheme | `DailyOPIc` (단일) |
| 결과 | **BUILD SUCCEEDED** |
| 에러 | **0건** |
| 경고 | 13건 — 전부 `GoogleMobileAds` umbrella header 관련 서드파티 경고. 앱 코드 유래 경고 없음 |

코드 수정 없이 as-is로 빌드/설치/실행까지 도달했다.

### 1.2 런타임 `[SIM]` — **1차 대비 변경**

```
Firebase App Check  → 성공 (Debug provider, tokenLength=940)
Firebase 익명 인증   → 성공
AppRootView         → .ready → MainTabView 정상 진입
```

1차에서 관찰된 `AuthRecoveryView` 정지는 **코드 버그가 아니라 시뮬레이터 디버그 토큰 미등록** 때문이었음이 확정됐다. 토큰 등록 후 재현되지 않는다.

`FirebaseBootstrap.configure()`는 시뮬레이터에서만 `AppCheckDebugProviderFactory`, 실기기에서는 `AppAttestProviderFactory`를 쓴다. **프로덕션 App Check는 약화되지 않았고 이번 audit에서도 건드리지 않았다.** `[CODE]`

부수 확인(1차와 동일): 콜드 런치 시 **ATT 프롬프트가 앱 UI보다 먼저 뜬다.** `[SIM]`

### 1.3 이 audit이 커버하는 범위

- `[SIM]`으로 도달·관찰한 **화면/시트 20개**, **상태 렌더링 40+종**
- 남은 `[CODE]`-only 영역과 `[UNVERIFIED]` 영역은 §10에 전부 명시

## 3. 주요 사용자 여정 — 실제 조작 기준 `[SIM]`

```
콜드 런치
 └─ SplashView                                   [SIM]
     └─ ATT 프롬프트 (시스템)                     [SIM]
         └─ 인증 성공 → AppRootView(.ready)       [SIM]
             ├─ isPresentingGuide      → OPIcGuideView      [SIM]
             ├─ !hasCompletedOnboarding → OnboardingView    [SIM]
             └─ else                    → MainTabView       [SIM]
```

> **구조적 사실 `[CODE]`**: 위 3분기는 `AppRootView`의 단일 `Group { switch }`다. 즉 가이드/온보딩/본체는 **서로를 대체(replace)** 하지, 위에 덮이지 않는다. 루트에 `NavigationStack`이 없고 시트도 아니다. 이 한 줄이 §7-1의 P0 원인이다.

### A. 데일리 (Practice) `[SIM]`

1. 문항 로드 → 가로 스크롤 chip(**Q2~Q15**) + `QuestionCard`
2. `질문 듣기`(TTS) → 마이크 탭 → 온디바이스 STT
3. 종료 → `AILoadingOverlay` → 결과 인라인 표시(`PracticeResultView(isEmbedded:)`)
4. 하단 `이전 / 다음` 네비게이션, 최하단 `BannerAdView`
5. 툴바: `?`(도움말) · 슬라이더(학습 설정) · 왕관(구독)

> chip이 **Q2부터 시작**하는 것은 버그가 아니다. `PracticeScreen.swift:145` 주석 `// 실제 문항 번호(데일리 Q2~Q15)` — Q1은 모의고사 자기소개 문항이라 데일리에서 제외된다. **의도된 동작.** 다만 사용자에게는 "Q1이 없는 앱"으로 보인다(§7-8).

### B. 모의고사 (MockExam) `[SIM]` — **여정 중단됨**

1. 인트로 → 배경 설문
2. 무료 사용자: **리워드 광고 2회 시청**
3. → `이어서 진행할 문제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`
4. `이어서 하기` 2회 재시도 → **screenHash 무변화. 로딩 표시도, 복구 경로도 없음.**

**무료 1회 모의고사 기회가 아무것도 제공하지 않은 채 소진됐다.** 상세는 §7-2.

### C. 통계 (Progress) `[SIM]`

`통계` 탭 → 기간 세그먼트(최근 7일 / 30일 / 전체) → 총 시도·최근 등급·연습·모의고사 카드 → 등급 분포 → 예상 등급 추이(빈 상태) → 취약 유형 분석 → 주간 리포트 → 최근 기록(+`전체 삭제`) → `BannerAdView`
→ 기록 탭 → `HistoryDetailView`(연습 상세) → 잠금 카드 탭 → `PaywallView` 시트

### D. 공통 진입점 `[SIM]`

- 툴바 `?` → `OPIcGuideView` (메뉴 → 가이드 페이지, 진행 바 + `다음`)
- 툴바 슬라이더 → `SetupView`(학습 설정, 네이티브 `List` + `NavigationStack`)
- 툴바 왕관 / 잠금 카드 → `PaywallView` 시트

## 4. 화면별 상태 감사

각 화면에 대해 default / loading / empty / error / disabled / 권한거부 / 네트워크실패 / 쿼터소진 / 무료 / 유료 / 재시도를 점검했다.

### 4.1 SplashView `[SIM]`

| 상태 | 현황 |
|------|------|
| default | 마이크 원형 아이콘 + `Text("DailyOPIc")` + `ProgressView` |
| loading | 이것이 유일한 상태 |

- 워드마크 `.font(.system(size: 40, ...))` **고정 크기** `[CODE]`
- 마이크 원 무한 펄스에 `accessibilityReduceMotion` 가드 없음 `[CODE]`

### 4.2 ATT 프롬프트 `[SIM]`

| 상태 | 현황 |
|------|------|
| default | 콜드 런치 직후, **앱이 어떤 가치도 보여주기 전에** 시스템 다이얼로그 |
| 거부 후 | 앱 진행. 사전 설명(pre-permission) 화면 없음 |

### 4.3 AuthRecoveryView `[SIM]` (1차 관찰, 이번엔 재현 안 됨)

| 상태 | 현황 |
|------|------|
| default | `wifi.exclamationmark` + "잠시 연결에 문제가 있어요" + "네트워크 상태를 확인하고 다시 시도해 주세요." |
| 상세 | `DisclosureGroup("자세히 보기")` 안에 원인 문자열 |
| 액션 | `PrimaryButton("다시 시도")` |
| loading | 재시도 중 라벨이 사라지고 스피너만 남음 `[CODE]` |

- **실제 원인은 App Check attestation 실패인데 화면은 "네트워크 문제"라고 말한다** `[SIM]`
  → 1차 판정 유지. 다만 §11에서 **P1 → P2로 강등**한다(사유 명시).
- Dark 모드 정상 적응 `[SIM]` / AX5에서 제목은 고정 크기, 버튼 라벨만 거대화 `[SIM]`

### 4.4 PracticeScreen `[SIM]` — **1차 `[CODE]` → 승격**

| 상태 | 현황 | 증거 |
|------|------|------|
| default | chip 행 + `데일리 토큰` 배지 + `QuestionCard` + `질문 듣기` + 마이크 + `내 답변` 플레이스홀더 + `이전/다음` + 배너 | `[SIM]` |
| loading(AI) | `AILoadingOverlay` 전체 차단 | `[SIM]` |
| error | 상단 인라인 `ErrorBanner` + `재시도` (`인식된 영어 답변이 없습니다. 다시 녹음해 주세요.`) | `[SIM]` |
| 녹음중 | 마이크 색 변화 + `탭하면 답변 완료` | `[SIM]` |
| 대기 | `탭하고 답변하기` | `[SIM]` |
| **처리중** | **전용 표현 없음** | `[SIM]`+`[CODE]` |
| **중단됨** | **전용 표현 없음** | `[CODE]` |
| **권한거부** | **전용 표현 없음** | `[CODE]` |
| 쿼터소진 | `데일리 토큰 0` 배지. 그러나 **남은 문항은 계속 응답 가능** | `[SIM]` |
| 무료 | 하단 `BannerAdView` 노출 (`Test mode` 라벨) | `[SIM]` |
| 유료 | 미확인 — 결제 미수행 | `[UNVERIFIED]` |
| 답변 완료 | 결과가 **인라인 치환**(`isEmbedded: true`). 별도 화면 전환 없음 | `[SIM]` |

**새로 관찰된 사실:**

1. **자동 종료·자동 제출** `[SIM]` — "Hello"만 말했는데 `완료`를 누르지 않았음에도 녹음이 스스로 끝나고 제출까지 진행돼 결과가 나왔다. 사용자가 "말을 마쳤다"고 선언하는 순간이 UI에 없다.
2. **`데일리 토큰 0`** `[SIM]` — 문항 세트가 로드되는 즉시 0으로 떨어지는데 응답 가능한 문항은 9개 이상 남아 있다. 토큰은 **세트 발급**을 게이팅하는데 배지는 "오늘 할 수 있는 횟수"처럼 읽힌다.
3. **툴바가 콘텐츠를 가린다** `[SIM]` — 스크롤 시 `데일리 토큰` 배지가 `?` 버튼 **아래로 파고들어 글자가 겹친다.** 툴바에 scroll-edge material/배경이 없다.
4. **하단 배너가 플로팅 탭바에 가려진다** `[SIM]` — `BannerAdView`가 ScrollView 최하단에 있고 탭바가 그 위에 뜬다. 스크롤 최하단에서도 배너 상단 일부만 보인다.

### 4.5 PracticeResultView / HistoryDetailView `[SIM]` — **1차 `[CODE]` → 승격**

| 상태 | 현황 |
|------|------|
| default | 문항 카드 → 면책 문구 → **등급 카드(IL / 목표 IM1 / 신뢰도 높음)** → `강점` → 잠금 카드들 → `답변 자세히 보기` → 하단 면책 |
| 무료 | `항목별 상세 분석`·`개선할 점` = 베이직 잠금 / `교정·모범답안`·`목표 등급까지` = 플러스 잠금 |
| 잠금 카드 탭 | `HistoryDetailView`에서는 **`PaywallView` 시트 정상 표시** `[SIM]` |
| 답변 자세히 보기 | `DisclosureGroup` — 펼치면 `내 답변` 전사 표시 `[SIM]` |

**새로 관찰된 사실:**

1. **"신뢰도 높음"이 3단어 답변에 붙는다** `[SIM]` — 전사 전문은 `Hello hello my name is`. 이 입력에 대해 앱은 `IL` 등급과 **`신뢰도 높음`** 을 표시한다. 학습자가 결과를 신뢰할 근거가 무너진다.
2. **`강점`이 실질적으로 비어 있다** `[SIM]` — `말을 시작하려는 시도는 있음.` / `문제 상황을 완전히 멈추지 않고 첫 발화는 했음.` 무료 사용자가 받는 유일한 피드백이 이것이다.
3. **잠금 카드가 화면마다 다르게 동작한다** — `HistoryDetailView`에서는 페이월이 열리지만, `PracticeScreen` 인라인 결과에서 같은 카드를 탭했을 때 **screenHash가 변하지 않았다**(1차 탐색 관찰). 동일 컴포넌트(`LockedFeedbackSection`)·동일 `.sheet` 바인딩인데 결과가 다르다. 재현 조건 미확정 → §10.3.
4. **`연습 상세` 헤더가 콘텐츠 위에 그냥 떠 있다** `[SIM]` — 스크롤하면 등급 카드의 `OPIc 예상 등급` 글자와 헤더 타이틀 `연습 상세`가 **겹쳐서 동시에 읽힌다.** 상태 표시줄 시계(`7:52`)도 콘텐츠와 겹친다.

### 4.6 MockExamScreen `[SIM]` — **1차 `[CODE]` → 승격, 판정 악화**

| 상태 | 현황 |
|------|------|
| 인트로 | 설명 + 시작 게이트 `[SIM]` |
| 설문 | 배경 설문 `[SIM]` |
| 시작 게이트(무료) | **리워드 광고 2회 연속** `[SIM]` |
| **시작 실패** | `이어서 진행할 문제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.` + `이어서 하기` `[SIM]` |
| 재시도 | **2회 시도, 화면 무변화. 로딩 인디케이터 없음.** `[SIM]` |
| 세션 포기 | **경로 없음** `[SIM]`+`[CODE]` |
| answering / 타이머 / 난이도 조정 / 결과 | **도달 실패** `[UNVERIFIED]` |

원인 `[CODE]` — `MockExamViewModel`:

```swift
private func enterResume(_ session: MockSession) async {
    var set = session.questionSet
    if set == nil { set = (try? await api.currentMockSession())?.questionSet }
    guard let set else {
        phase = .introduction
        errorMessage = "이어서 진행할 문제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요."
        return
    }
```

서버에 세션은 존재하는데 `questionSet`이 없다. `performStart`도 `guard let set = started.questionSet else { throw ... }`로 같은 벽에 부딪힌다. **세션을 버리고 새로 시작하는 클라이언트 경로가 없다.**

### 4.7 ProgressScreen (통계) `[SIM]` — **1차 `[CODE]` → 승격**

| 상태 | 현황 |
|------|------|
| default | 기간 세그먼트 + 요약 4카드 + 등급 분포 + 예상 등급 추이 + 취약 유형 분석 + 주간 리포트 + 최근 기록 + 배너 |

2. 툴바 `?`(도움말) 탭 → 가이드 진입
3. 가이드 닫기
4. **돌아온 화면: Q2로 리셋. ✓ 사라짐. Q2 결과 사라짐. `내 답변` 빈 상태. 에러 배너 사라짐.**
5. **`데일리 토큰`은 여전히 `0`** → 새 세트를 받을 수도 없다

**원인 `[CODE]` — `AppRootView.swift:9-28`:**

```swift
Group {
    switch environment.launchState {
    case .ready:
        if environment.preferences.isPresentingGuide {
            OPIcGuideView(...)                 // ← MainTabView를 대체
        } else if ... {
            MainTabView(environment: environment)
```

가이드는 시트가 아니라 **`MainTabView`를 대체**한다. 따라서 `MainTabView`와 모든 하위 `@State`/`@StateObject`(진행 중 세션, 응답 결과, 현재 문항 인덱스, 에러 상태)가 통째로 해제된다. 닫으면 처음부터 다시 생성된다.

같은 경로가 **3개** 있다:
- 툴바 `?` → `GuideEntryButton` → `beginGuide()`
- 학습 설정 → `도움말 다시 보기` → `beginGuide()`
- 학습 설정 → `난이도 바꾸기` → `resetOnboarding()` → `OnboardingView`로 대체

즉 **"도움을 요청하는 행위"와 "설정을 바꾸는 행위"가 학습 결과를 삭제한다.** 도움이 가장 필요한 순간(막혔을 때)에 정확히 발동한다.

> 결과 자체는 로컬 기록(통계 → 최근 기록)에 남는다. 잃는 것은 **진행 중 세션 상태**다. 그러나 토큰이 0이면 세트를 다시 받을 수 없으므로 **그날의 학습은 사실상 종료**된다.

### 7-2. 모의고사가 광고 2편을 태우고 데드엔드에 빠진다 — **P0** `[SIM]`+`[CODE]` 🆕

§4.6. 무료 사용자 관찰 결과:

1. 인트로 → 설문 → **리워드 광고 2회 시청**
2. `이어서 진행할 문제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.`
3. `이어서 하기` **2회** → 화면 무변화(screenHash 동일). 로딩 표시 없음
4. **세션을 버리고 새로 시작하는 경로 없음**

무료 1회 체험이 **아무 산출물 없이 소진**됐다. 사용자 관점에서 이것은 "광고 두 편 보고 아무것도 못 받음"이다. 유료 전환 판단에 직결되는 첫 경험이 이것이다.

기술적으로: 서버 세션은 존재하나 `questionSet`이 비어 있고, 클라이언트에 abandon/reset 경로가 없다. 재시도는 같은 깨진 세션을 계속 다시 읽는다.

### 7-4. 오디오 중단 시 녹음이 조용히 사라진다 — **P0** `[CODE]`

`SpeechRecognitionService.handleInterruption`(231행):

```swift
@objc private func handleInterruption(_ notification: Notification) {
    guard isListening else { return }
    interruptionReason = "통화 또는 다른 오디오로 녹음이 중단됐습니다. 같은 문항에서 다시 시작해 주세요."
    recordingState = .interrupted
    errorMessage = interruptionReason
    cancel()
    recordingState = .interrupted
}
```

**재확인 결과(grep 전수):** `interruptionReason`을 읽는 View/ViewModel이 **여전히 0개**다. 문구는 이미 코드에 있는데 화면이 읽지 않는다.

추가로 발견 `[CODE]`: 이 핸들러는 `notification.userInfo`의 `AVAudioSessionInterruptionType`을 **검사하지 않는다.** `.began`과 `.ended`를 구분하지 않으므로 중단 종료 알림도 같은 코드를 탄다(현재는 `isListening == false`라 무해하지만, 재개(resume) 처리를 넣는 순간 함정이 된다).

MockExam에서는 같은 화면에 `한 번 답한 문항은 다시 답할 수 없어요.`가 떠 있다. **전화 한 통이 모의고사 한 문항을 영구히 날리면서 아무 설명도 하지 않는다.**

> 시뮬레이터에서 통화 인터럽션을 재현하지 못했으므로 여전히 `[CODE]`다. 다만 §7-5의 자동 종료 관찰은 "녹음이 사용자 의사와 무관하게 끝날 수 있다"는 점을 실증한다.

### 7-5. 녹음이 사용자 선언 없이 끝나고 자동 제출된다 — **P0** `[SIM]` 🆕

"Hello"만 말했는데 `완료`를 누르지 않았음에도 **녹음이 스스로 종료되고 제출·채점까지 진행**됐다. 그 결과가 `IL` + **`신뢰도 높음`**이다.

말하기 학습에서 "내가 말을 마쳤다"를 선언하는 순간은 **사용자에게 있어야 한다.** 지금은 앱이 대신 결정하고, 그 결정에 대한 취소·되돌리기도 없다. §7-6과 결합하면 **잘못 잘린 답변에 대해 앱이 자신 있게 등급을 매긴다.**

### 7-6. 3단어 답변에 "신뢰도 높음" — **P1** `[SIM]` 🆕

전사 전문 `Hello hello my name is`에 대해 `OPIc 예상 등급 IL` + `신뢰도 높음`.

`신뢰도`는 앱이 사용자에게 "이 결과를 믿어도 된다"고 말하는 유일한 장치다. 그 장치가 명백히 무의미한 입력에서 최고값을 낸다. 한 번 겪으면 **모든 결과에 대한 신뢰가 무너진다.** 이건 시각 디자인이 아니라 **제품 신뢰성** 문제다.

### 7-7. 6종 녹음 상태가 Bool 하나로 붕괴 — **P1** `[SIM]`+`[CODE]`

`recordingState`: `idle` / `recording` / `processing` / `interrupted` / `failed` + 별도 `permissionState`.
UI가 읽는 것: **`speech.isListening` Bool 하나** (`PracticeScreen` 5곳, `MockExamScreen` 4곳 — grep 전수).

`.processing` 구간에 `stop()`이 250ms sleep + M4A 압축을 수행하는데 그동안 `isListening == false`라 화면은 **`탭하고 답변하기`(= 준비됨)** 를 보여준다. §7-5에서 관찰한 "자동 종료 후 결과가 튀어나오는" 체감이 여기서 나온다. 마이크 권한 거부 전용 화면도 없다.

### 7-8. `데일리 토큰 0`이 잘못된 메시지를 준다 — **P1** `[SIM]` 🆕

## 9. 다음 디자인 단계에서 반드시 해결해야 할 것 (10개)

> 이 문서는 설계를 하지 않는다. "무엇을 반드시 다뤄야 하는가"만 남긴다.

1. **네비게이션 셸을 다시 세운다 — 화면을 "대체"하지 않는다.**
   지금 가이드·온보딩·난이도 변경은 `MainTabView`를 통째로 갈아치우고, 그 결과 학습 세션이 삭제된다(P0-1). 이건 화면 하나의 버그가 아니라 **루트 구조**의 문제다. 시트/스택 기반 계층으로 재정의하지 않으면 어떤 화면을 새로 그려도 같은 손실이 재발한다.

2. **타이포그래피 시스템을 Dynamic Type 위에 다시 세운다.**
   `AppTypography` 7종이 전부 절대 크기이고 `relativeTo:`가 0회다. AX5에서 **녹음 버튼이 화면 밖으로 밀려나고**, **등급 `IL`이 주변 라벨보다 작게** 렌더링된다. 목업을 medium에서만 그리면 같은 문제를 다시 만든다. **가장 큰 글자 크기에서 성립하는 레이아웃이 기준선**이어야 한다.

3. **말하기 상태를 1급 UI 개념으로 승격하고, "끝"의 주도권을 사용자에게 돌려준다.**
   `준비 / 녹음중 / 처리중 / 중단됨 / 실패 / 권한없음` 6개 상태에 각각 표현이 필요하다. 동시에 **자동 종료·자동 제출**(P0-5)을 재설계해야 한다. 말하기 앱에서 "말을 마쳤다"는 선언은 학습자의 것이다.

4. **결과의 신뢰 표현을 근거와 묶는다.**
   `신뢰도 높음`이 3단어 답변에 붙는 순간(P1-1) 앱의 모든 숫자가 의심받는다. 신뢰도·등급·취약 유형은 **입력 품질(발화 길이·인식 신뢰도·묵음 비율)이 임계 이하일 때 다른 화면**을 보여줘야 한다. 취약 유형이 전부 동일값일 때 막대 5개를 그리는 것도 같은 문제다(P2-1).

5. **실패에서 빠져나오는 길을 모든 플로우에 만든다.**
   모의고사 데드엔드(P0-2)의 본질은 "세션을 버릴 수 없다"는 것이다. 오디오 중단(P0-4)도, 재시도 무반응도 같은 뿌리다. **모든 에러 상태는 (원인 · 다음 행동 · 포기 경로) 3요소를 갖는다**를 시스템 규칙으로 둔다. 특히 **광고·토큰을 이미 소비한 실패는 소비를 되돌리거나 보상해야 한다**(정책 결정 사항 — 임의 변경 금지).

6. **화폐 경로(페이월·구독)를 접근 가능한 1급 컴포넌트로 재구성한다.**
   구매가 `.onTapGesture`(P0-3)인 것, 설정에 관리·복원·문의가 없는 것(P1-6)은 같은 원인이다 — **결제 UI가 컴포넌트 시스템 밖에 있다.** 주 CTA 하나, 추천 플랜 강조, 부정 항목의 별도 표기(✓ 금지), 관리·복원·약관의 상시 접근 경로를 함께 정의한다.

7. **레이아웃 셸(safe area · scroll edge · 플로팅 요소)을 한 번에 정의한다.**
   툴바 겹침, 상태 표시줄 겹침, 시트 헤더 겹침, 탭바에 가려진 배너(P1-4)가 **전부 같은 원인**이다. 화면별로 패딩을 더하는 방식으로는 끝나지 않는다. 스크롤 컨테이너 + 헤더 material + 하단 inset을 **셸 레벨에서 한 번** 정한다.

8. **모달을 하나의 패턴으로 통합한다.**
   현재 4가지 방식이 공존한다(네이티브 시트 / 네이티브 알럿 / 커스텀 오버레이 6개 / 루트 교체). 커스텀 오버레이는 `.isModal` 0개, 스크림 3종이며 실제로 배경이 다 읽힌다. **스크림 값·전환 모션·`.isModal`·dismiss 방식을 한 곳에서** 결정한다.

9. **터치 타깃 44pt를 컴포넌트에 내장한다.**
   chip 22~24pt는 개별 실수가 아니라 **작은 인터랙티브 요소용 공용 컴포넌트가 없기 때문**이다. chip/pill 컴포넌트에 최소 높이와 `contentShape` 확장을 내장해야 재발하지 않는다.

10. **다크 모드를 라이트의 파생이 아니라 동등한 대상으로 설계한다.**
    현재 accent는 밝기만 올린 값이고, 실제로 **등급 카드에서 흰 글자가 연보라 위에 놓여 가장 중요한 정보가 가장 안 읽힌다.** 팔레트 정의 시점에 **양쪽 모드의 대비를 각각 측정**한다.
