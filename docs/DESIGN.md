# DailyOPIc — DESIGN.md

**이 문서는 DailyOPIc 제품 리뉴얼의 UX/UI single source of truth다.**

작성일: 2026-08-08
전제 문서: `docs/PRODUCT.md` · `docs/audit/UI_BASELINE_AUDIT.md` · `docs/DESIGN_DECISIONS.md` (Q1–Q9 LOCKED)
상태: **설계 확정 문서. 구현 시작 전.**

### 이 문서의 규칙

1. **현재 구현되지 않은 기능을 새 기능처럼 만들어내지 않는다.** 모든 화면·상태·데이터는 실제
   iOS 코드 또는 FastAPI 응답에 근거가 있다. 근거가 없으면 "미구현 — 범위 밖"으로 명시한다.
2. **임의의 수치를 발명하지 않는다.** 특히 A/B/C 버킷 임계값(단어 수·WPM·무음 비율)은
   `DESIGN_DECISIONS.md` Q2 LOCKED 제약에 따라 **이 문서에서 정하지 않는다.**
3. **가짜 정밀도를 만들지 않는다.** 서버가 5단계 밴드로 계산한 것을 100점 척도로 보여주지 않는다.
4. 대비·크기 등 수치는 **계산 또는 코드 확인으로 검증된 값만** 적는다.

### 디자인 방향

`native iOS` · `focused` · `trustworthy` · `calm` · `modern` · `learning-oriented` · `speaking-first`

# 1. Product design principles

리뉴얼의 모든 결정은 아래 7원칙에 종속된다. 원칙 간 충돌 시 **번호가 빠른 쪽이 이긴다.**

### P1. Speaking first — 말하기가 화면의 주인이다

이 앱의 핵심 행위는 "영어로 말한다" 하나다. 모든 화면에서 **말하기 흐름을 방해하는 요소는 제거하거나
뒤로 물린다.** 말하기 중에는 광고·업셀·통계·부가정보가 화면에 없어야 한다.

> 근거: Q5 LOCKED — 데일리 발화 흐름에서 배너 제거.

### P2. Trustworthy over impressive — 모르는 것은 모른다고 말한다

AI가 확신할 수 없을 때 확신하는 척하지 않는다. 3단어 답변에 "IL · 신뢰도 높음"을 보여주는 현재 동작은
**제품 신뢰를 파괴하는 버그**로 취급한다. 근거 없는 등급·점수·퍼센트는 표시하지 않는다.

> 근거: Q2 LOCKED 제약 3 — B/C 상태에서 근거 없이 높은 예상 등급을 보여주지 않는다.

### P3. Nothing is lost — 사용자의 노력은 사라지지 않는다

녹음·답변·진행 상태는 화면 전환·설정 진입·앱 이탈·전화 수신으로 사라지지 않는다.
사라진다면 그것은 UI 문제가 아니라 **상태 소유권 설계 실패**다.

> 근거: T1 — `MainTabView`가 ViewModel을 `@State`로 소유해 루트 교체 시 파괴됨.

### P4. Always an exit — 막다른 화면을 만들지 않는다

모든 화면·모달·게이트·오류 상태에는 **최소 하나의 진행 가능한 행동**이 있어야 한다.
"다시 시도"만 있고 그 재시도가 실패하는 상태는 탈출구가 아니다.

> 근거: T2 — 모의고사 데드엔드에서 "이어서 하기"와 "포기"가 동시에 사라짐.

### P5. Calm surface — 조용한 화면이 집중을 만든다

장식용 그림자·그라디언트·글래스·애니메이션을 쓰지 않는다. 시각적 강조는 **위계·여백·타이포**로 만든다.
화면에 카드가 많다는 것은 정보 구조를 정리하지 못했다는 뜻이다.

### P6. One primary action — 화면마다 주 행동은 하나

주 CTA는 화면당 하나다. 나머지는 시각적으로 종속된다. 동등해 보이는 카드 4장을 나열하고
사용자에게 고르라고 하지 않는다.

> 근거: T6 — 페이월 4개 동등 카드, 주 CTA 없음.

### P7. Accessible by construction — 나중에 붙일 수 없는 것부터 정한다

Dynamic Type 대응, 시맨틱 컨트롤, 44pt 터치 타깃, 모달 포커스는 **컴포넌트 설계 시점의 결정**이다.
구현 후에 붙이는 것이 아니라, 붙일 수 없는 컴포넌트를 애초에 만들지 않는다.

> 근거: T8 — `relativeTo:` 0건, `.isModal` 0건, `onTapGesture` 액션 7건.

# 2. Core user journey

## 2.1 주 여정 — 데일리 말하기 (하루 1회, 5–10분)

```
앱 실행
  └ 스플래시(인증·capabilities 로드)
      └ [최초 1회] 온보딩: 목표 등급 선택 → 배경 설문 → 가이드
      └ 데일리 홈
          ├ 오늘의 세트 상태 확인 (남은 새 문제 세트 · 현재 세트 진행도)
          ├ 문항 선택 (14문항 중)
          └ 말하기 루프  ←──────────────────────┐
              ├ ready     문항 읽기 / 프롬프트 듣기 │
              ├ recording 말하기 (최대 180초)      │
              ├ finishing 종료 처리                │
              ├ processing 전사 확인 ─ 다시 녹음 ──┘
              ├ analyzing AI 분석
              └ result    A(평가 가능) / B(신뢰 낮음) / C(평가 불가)
                  ├ A → 다음 문항 또는 결과 상세
                  ├ B → 근거 표시 + 더 말해보기 유도
                  └ C → 등급 없음 + 다시 말하기
```

**여정의 핵심 사실 (T3 검증):** 세트 안 14문항은 **무제한 답변·재답변·재평가**가 가능하다.
토큰은 *새 세트를 받을 때만* 소모된다. 이 사실이 여정 전체의 심리적 안전망이므로 UI가 반드시 전달한다.

## 2.2 부 여정 — 모의고사 (실전 시뮬레이션)

```
모의고사 탭
  └ 인트로 (오늘 응시 가능 여부 · 광고 게이트 안내)
      └ 설문 선택 (또는 저장된 설문 재사용)
          └ [게이트 1] 시작        무료: 광고 1편 / 유료: 즉시
              └ 앞 7문항 답변 (문항당 180초)
                  └ [게이트 2] 난이도 조정   무료: 광고 1편 / 유료: 즉시
                      └ 뒤 8문항 답변
                          └ [게이트 3] 결과   무료: 광고 1편 / 유료: 즉시
                              └ 결과
```

각 단계에서 **이탈 가능**하고, 이탈 후 **정확히 그 지점으로 복귀**한다. 언제든 **포기 가능**하며
포기하면 같은 날 다시 시작할 수 있다(Q9 LOCKED — backend abandon endpoint 필요).

## 2.3 보조 여정

| 여정 | 진입 | 비고 |
|---|---|---|
| 결과 다시 보기 | 통계 → 기록 | 로컬 SwiftData. 기간 제한 없음(Q6 LOCKED) |
| 목표 등급 변경 | 설정 → 난이도 바꾸기 | 하루 1회. 무료 광고 1편 / 유료 즉시 |
| 가이드 다시 보기 | 설정 → 도움말 | 읽기 전용 |
| 구독 | 페이월(4개 진입점) | 월 구독 3종. 무료 체험 없음 |
| 복원·관리 | 페이월 하단 | 구매 복원 · 구독 관리(유료만) |

# 3. Information architecture

## 3.1 전체 구조

```
DailyOPIc
├── 데일리 (Tab 0)  ← 홈. 앱의 중심
│   ├── 오늘 상태 (남은 새 문제 세트 · 현재 세트 진행도)
│   ├── 문항 선택 (14문항)
│   ├── 말하기 (8상태)
│   └── 결과 (A / B / C)
├── 모의고사 (Tab 1)
│   ├── 인트로 · 설문
│   ├── 게이트 (시작 / 조정 / 결과)
│   ├── 답변 (15문항 · 문항당 180초)
│   └── 결과
├── 캘린더 (Tab 2)  ← G2. 오늘 할 일이 먼저, 달력은 보조
│   ├── 학습 계획 온보딩 (5단계 · 미설정 시)
│   ├── 목표 요약 (예상 기간 · 완료 예상일 · 시험 D-n)
│   ├── 이번 주 (월~일 스트립)
│   ├── 오늘의 학습 → "Daily 연습 시작"(데일리 탭으로 이동)
│   └── 월간 보기 (보조)
├── 통계 (Tab 3)
│   ├── 예상 등급 추이
│   ├── 취약 유형
│   ├── 주간 리포트
│   └── 학습 기록
└── 설정 (모달 · 탭 아님)
    ├── 목표 등급 · 배경 설문
    ├── 도움말
    ├── 구독 관리
    └── 약관 · 개인정보 · 문의
```

## 3.2 계층 원칙

- **4탭.** G2에서 `캘린더`가 추가됐다(학습 계획은 상시 참조하는 목적지라 모달이 아니다).
  설정은 여전히 탭이 아니라 모달이다. 여기서 더 늘리지 않는다.
- **깊이 최대 3.** 탭 → 화면 → 상세. 그 이상 들어가면 정보 구조를 다시 본다.
- **모의고사는 자체 완결.** 시험 중에는 다른 탭으로의 이동을 막지 않되, 돌아오면 정확히 그 지점이다.
- **통계는 읽기 전용.** 통계에서 학습을 시작하지 않는다. 학습 진입점은 데일리 홈 하나다.

## 3.3 명명 규칙 (T3 LOCKED 반영)

| 폐기 | 채택 | 이유 |
|---|---|---|
| "데일리 토큰" | **"오늘의 새 문제"** | 토큰 = 게임 재화 은유. 실제 단위는 "새 문제 세트" |
| "분석 N회 남음" | **"새 문제 N세트 남음"** | 분석은 무제한. 서버 계약과 정반대 표현 |
| "남은 문항" | **"이 세트 진행도 n/14"** | 문항은 소진 자원이 아님 |

> **금지 카피:** "토큰", "크레딧", "분석 횟수", "남은 평가 횟수".
> 이 단어들은 세트 내 평가가 무제한(Q3 LOCKED)이라는 사실과 충돌한다.
>
> **예외(G1·G2):** 페이월과 캘린더에서 **플랜 한도를 말할 때만** "데일리 토큰"을 쓴다
> ("현재 무료 플랜 최대 1토큰"). 이때 토큰은 분석 횟수가 아니라 하루에 받을 수 있는
> 새 문제 세트 수를 가리키며, 학습 화면 카피에는 여전히 쓰지 않는다.

# 4. Navigation architecture

## 4.1 루트 계약

**루트 분기는 인증/부팅 상태만 표현한다. 제품 모드는 절대 루트 분기로 표현하지 않는다.**

```
AppRootView
├── .launching → SplashView
├── .failed    → AuthRecoveryView
└── .ready     → MainTabView          ← .ready의 유일한 자식
                  ├ .fullScreenCover: 온보딩 (목표 등급 · 설문)
                  └ .fullScreenCover: 가이드
```

현재는 가이드·온보딩이 `MainTabView`를 **교체**한다(`AppRootView.swift:6-38`).
리뉴얼 후에는 **위에 덮는다.** 이것이 §5 세션 보존의 전제다.

## 4.2 제시 방식 결정표

| 대상 | 방식 | 근거 |
|---|---|---|
| 탭 전환 | `TabView` | 최상위 3개. 유지 |
| 화면 내 상세(결과 상세 등) | `NavigationStack` push | 뒤로가기 제스처 자연스러움 |
| 설정 | `.sheet` | 이탈 가능·비파괴적. 현재 방식 유지 |
| 페이월 | `.sheet` | 언제든 닫을 수 있어야 함 |
| 온보딩(목표 등급·설문) | **`.fullScreenCover`** | 몰입형 + 스와이프 중도 이탈 금지(광고/서버 상태 변경 동반) |
| 가이드 | **`.fullScreenCover`** | 온보딩과 시각 언어 통일 |
| 확인 다이얼로그(포기·되돌리기) | `.confirmationDialog` / `.alert` | **커스텀 오버레이 대체.** 시스템 접근성·포커스 무료 |
| 광고 게이트 | 인라인 화면 (모달 아님) | 시험 흐름의 일부. 별도 모달은 맥락을 끊음 |
| 로딩 오버레이 | 인라인 상태 + `.regularMaterial` 스크림 | §15 |

## 4.3 뒤로가기 계약

- 뒤로가기는 **항상 예측 가능**하다. 스크롤 위치·필터·입력 상태를 복원한다.
- 시스템 스와이프-백 제스처를 막지 않는다. **단 `.fullScreenCover` 2종은 제외**(명시적 완료/닫기 버튼).
- 네비게이션 스택을 조용히 리셋하지 않는다. 홈으로 튀는 동작 금지.

## 4.4 모의고사 특례

모의고사 진행 중 탭을 벗어나도 **세션은 서버와 로컬 드래프트 양쪽에 살아 있다**
(`currentMockSession()` + `MockDraftRecord`). 돌아오면 서버 stage 기준으로 정확한 지점에 복귀한다(§22.3).

# 5. Session preservation rules

## 5.1 상태 소유권 계층 (핵심 아키텍처 결정)

```
DailyOPIcApp
└── AppEnvironment                      ← 앱 생명주기 전체를 산다
    ├── preferences / persistence / authentication / api / ads / store
    ├── launchState / capabilities
    ├── practiceViewModel               ← 【이동】 MainTabView.@State → 여기
    └── mockViewModel                   ← 【이동】 MainTabView.@State → 여기
```

**변경의 전부는 이 한 줄이다.** `PracticeViewModel`/`MockExamViewModel`의 소유자를
`MainTabView`의 `@State`에서 `AppEnvironment`의 저장 프로퍼티로 올린다.
두 클래스 모두 `@MainActor @Observable`이므로 뷰 코드 변경은 참조 경로뿐이다.

## 5.2 보존 규칙 (R1–R6)

| # | 규칙 | 적용 |
|---|---|---|
| **R1** | **루트 교체는 인증 상태 변화에만 허용된다.** | 가이드·온보딩은 cover로 전환(§4.1) |
| **R2** | **진행 중 세션 state는 root보다 오래 산다.** | ViewModel을 `AppEnvironment`가 소유 |
| **R3** | **탭 전환은 어떤 세션도 파괴하지 않는다.** | `TabView`는 이미 뷰를 유지. R2로 완결 |
| **R4** | **녹음 중 인터럽션은 오디오를 보존한다.** | 현재는 `cancel()`이 파일을 삭제(§17.4) |
| **R5** | **앱 종료/크래시 후 재진입 시 진행 상태를 복원한다.** | 모의고사는 구현됨. **데일리에도 드래프트 추가** |
| **R6** | **서버 세션과 클라이언트 상태는 갈라지지 않는다.** | 포기 시 서버 세션도 종료(Q9 LOCKED) |

## 5.3 데일리 드래프트 (R5 신규)

현재 `PracticeViewModel`에는 복구 수단이 전혀 없다. 모의고사의 `MockDraftRecord` 패턴을 재사용해
아래 최소 항목만 저장한다. **신규 스키마 개념을 만들지 않는다.**

- 현재 세트 식별자 · 현재 문항 인덱스 · 분석 완료된 문항 결과(`analyzedResults`)

> 저장하지 않는 것: 진행 중이던 오디오 버퍼(파일 시스템 임시 파일이며 앱 재시작 시 무의미).

## 5.4 세션 파괴가 허용되는 유일한 경우

1. 사용자가 **명시적으로** 포기/초기화를 선택했을 때 (확인 다이얼로그 경유)
2. 날짜가 바뀌어 서버 세션이 만료됐을 때 (KST 자정)
3. 로그아웃/계정 전환 (현재 익명 인증만 있어 해당 없음)

그 외 어떤 경우에도 세션은 파괴되지 않는다.

## 6.3 Typography

### 전략: iOS 텍스트 스타일로 1:1 매핑 (Dynamic Type 무료 획득)

현재 `AppTypography`의 7종은 **전부 절대 크기**라 Dynamic Type에 대응하지 못한다(`relativeTo:` 0건).
그런데 확인해보니 **현재 크기가 iOS 표준 텍스트 스타일 기본 크기와 정확히 일치한다.**

| 현재 | 크기/굵기 | → iOS 텍스트 스타일 | 기본 크기 | 일치 |
|---|---|---|---|---|
| `title` | 28 bold | `.title` | 28 | ✅ |
| `cardTitle` | 22 bold | `.title2` | 22 | ✅ |
| `sectionTitle` | 17 semibold | `.headline` | 17 semibold | ✅ |
| `body` | 16 regular | `.callout` | 16 | ✅ |
| `callout` | 15 medium | `.subheadline` | 15 | ✅ |
| `footnote` | 13 regular | `.footnote` | 13 | ✅ |
| `caption` | 12 semibold | `.caption` | 12 | ✅ |

→ **기본 Dynamic Type 크기에서 시각적 회귀가 0인 채로 전 구간 스케일링을 얻는다.**

```
title        →  Font.system(.title,       design: .rounded).weight(.bold)
cardTitle    →  Font.system(.title2,      design: .rounded).weight(.bold)
sectionTitle →  Font.system(.headline,    design: .rounded)
body         →  Font.system(.callout,     design: .rounded)
callout      →  Font.system(.subheadline, design: .rounded).weight(.medium)
footnote     →  Font.system(.footnote,    design: .rounded)
caption      →  Font.system(.caption,     design: .rounded).weight(.semibold)
```

`design: .rounded`는 유지한다. 학습 앱의 친근한 톤을 만들면서 시스템 폰트이므로 로딩 비용이 없다.

### 추가 규칙

- **숫자에는 `.monospacedDigit()`** — 타이머(180초 카운트다운), 남은 세트 수, 진행도 n/14.
  현재는 매초 자릿수가 바뀌며 레이아웃이 흔들린다.
- **본문 최소 크기는 `.footnote`(13pt).** 그보다 작은 텍스트를 만들지 않는다.
- 줄 수 제한은 **자르기보다 줄바꿈을 우선**한다. 불가피하게 자를 때만 `.truncationMode(.tail)`.
- `lineLimit(nil)` + `fixedSize(horizontal: false, vertical: true)`를 카드 본문의 기본으로 한다.
  AX 크기에서 텍스트가 잘리는 사고를 구조적으로 막는다.

## 6.4 Spacing

현재 `AppSpacing` = 6 / 10 / 16 / 22 / 28 — **4pt 그리드에서 벗어나 있다**(6, 10, 22).
리뉴얼 시점에 정렬한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `xs` | 4 | 아이콘–라벨 간격, 인라인 요소 |
| `sm` | 8 | 밀접한 요소 그룹, **터치 타깃 간 최소 간격** |
| `md` | 16 | 카드 내부 패딩, 기본 요소 간격 |
| `lg` | 24 | 섹션 간격, 화면 좌우 여백 |
| `xl` | 32 | 주요 블록 구분 |
| `xxl` | 48 | 화면 상단 여백, 빈 상태 |

- 화면 좌우 기본 여백은 **`lg`(24)**. 카드 안 콘텐츠 여백은 **`md`(16)**.
- 여백은 장식이 아니라 **그룹핑 도구**다. 관련된 것은 가깝게, 무관한 것은 멀게.

## 6.5 Radius

| 토큰 | 값 | 용도 |
|---|---|---|
| `control` | 12 | 버튼, 칩, 입력 |
| `card` | 16 | 카드, 섹션 컨테이너 |
| `sheet` | 24 | 바텀시트, 큰 오버레이 |

**모든 코너는 `RoundedRectangle(cornerRadius:style: .continuous)`를 사용한다.**
현재 코드는 기본값(`.circular`)이라 iOS 네이티브 컴포넌트와 곡률이 미묘하게 다르다.
이 한 줄이 "native iOS" 인상에 실제로 기여한다.

## 6.6 Elevation / Material

**이 앱에는 그림자가 없다.** 계층은 **배경색 레이어링 + 구분선**으로 만든다.

| 레벨 | 표현 | 용도 |
|---|---|---|
| **L0** | `bgBase` | 화면 배경 |
| **L1** | `surface` | 카드·섹션 (그림자 없음) |
| **L2** | `surfaceElevated` | 시트·다이얼로그 (시스템이 그림자 처리) |
| **L3** | `.regularMaterial` | 스크림·오버레이 **전용** |

### Material 사용 규칙

- **Material은 "뒤가 비활성"임을 알리는 신호일 때만 쓴다.** 장식으로 쓰지 않는다.
- 스크림 불투명도는 **한 값으로 통일**한다. 현재 커스텀 오버레이 3종이 0.28 / 0.32 / 0.34로 제각각이다.
  → `.regularMaterial` 단일 사용으로 대체하면 값 자체가 사라진다.
- **금지:** 카드에 `.ultraThinMaterial`, 그라디언트 배경, `shadow(radius:)` 장식.

# 7. Dynamic Type strategy

## 7.1 지원 범위

**`xSmall` ~ `AX5` 전 구간을 지원한다.** 축소하지 않는다.

## 7.2 3단계 적응 전략

| 구간 | 전략 |
|---|---|
| `xSmall` – `xxxLarge` | 기본 레이아웃. 텍스트만 스케일. 구조 변경 없음 |
| `AX1` – `AX2` | 가로 배치 → 세로 스택 전환. 보조 정보 축약 |
| `AX3` – `AX5` | **주 행동만 남긴다.** 보조 정보는 접거나 스크롤로 밀어냄 |

전환 판단은 `@Environment(\.dynamicTypeSize)`의 `.isAccessibilitySize`로 한다.
개별 픽셀 브레이크포인트를 만들지 않는다.

```
// 패턴 (구현 시 참조)
@Environment(\.dynamicTypeSize) private var typeSize

var body: some View {
    if typeSize.isAccessibilitySize { VStack(alignment: .leading) { ... } }
    else                            { HStack { ... } }
}
```

`ViewThatFits`는 두 레이아웃이 정말 등가일 때만 쓴다. 정보 우선순위가 달라지면 명시적 분기를 쓴다.

## 7.3 절대 축소되면 안 되는 요소 (AX5에서도 화면 안)

1. **녹음 버튼** — AX5에서 화면 밖으로 밀려나는 현재 버그가 최우선 수정 대상
2. 각 화면의 주 CTA
3. 모달의 닫기/완료 버튼
4. 모의고사 남은 시간
5. 오류 상태의 복구 액션

이들은 스크롤 콘텐츠가 아니라 **고정 영역(§10.4)에 배치**해 구조적으로 보장한다.

## 7.4 검증 방법

```
xcrun simctl ui <udid> content_size <size>
# size: extra-small … accessibility-extra-extra-extra-large
```

11개 화면 × 7단계(xSmall / Large / xxxLarge / AX1 / AX3 / AX5) 스크린샷 비교를 릴리스 체크리스트에 넣는다.
통과 조건: **텍스트 잘림 없음 · 주 액션 도달 가능 · 가로 스크롤 없음.**

# 8. Light / Dark Mode strategy

## 8.1 원칙

- **다크 모드는 반전이 아니다.** 색을 뒤집지 않고, 각 모드에 맞는 톤을 별도로 정의한다
  (현재 `AppPalette`의 `dynamic(light:dark:)` 구조가 이미 옳다 — 유지).
- **대비는 모드별로 따로 검증한다.** §6.2에서 확인했듯 라이트에서 통과한 조합이 다크에서 실패한다.
- 시스템 색(`.systemBackground`, `.label`, `.separator`)을 쓸 수 있는 곳에서는 커스텀 색을 만들지 않는다.
  시스템 색은 다크 모드·고대비 모드·Elevated 컨텍스트를 자동 처리한다.

## 8.2 모드별 차이 규칙

| 항목 | 라이트 | 다크 |
|---|---|---|
| 액센트 채도 | 원색 (`#4B24FF`) | **탈채도·밝게** (`#967AFF`) |
| 액션 위 라벨 | 흰색 | **`textPrimary`(어두움)** ← §6.2 수정 필요 2 |
| 카드 구분 | 배경색 차이 | 배경색 차이 + `separator` 보강 |
| 녹음 상태 | `.systemRed` | `.systemRed` (시스템이 톤 조정) |

## 8.3 하드코딩 금지

`Color.white` / `Color.black` / 리터럴 hex를 뷰에서 직접 쓰지 않는다.
전부 §6.2 토큰을 경유한다. 예외: `.regularMaterial` 위 텍스트처럼 시스템이 보장하는 조합.

## 8.4 검증

```
xcrun simctl ui <udid> appearance light|dark
```

# 9. Accessibility acceptance criteria

**아래 13개 기준은 리뉴얼의 Definition of Done이다.** 각 항목은 실제 검증 절차와 통과 조건을 갖는다.
(출처: `DESIGN_DECISIONS.md` T8. 이 문서에서 확정 기준으로 승격)

| # | 항목 | 통과 조건 | 검증 |
|---|---|---|---|
| **A1** | VoiceOver 라벨 | 모든 인터랙티브 요소가 비어 있지 않은 label 보유. 타입명만 읽히는 요소 **0개** | Inspector Audit + 8개 여정 수동 주행 |
| **A2** | VoiceOver 순서 | 읽기 순서 = 시각 순서. 오버레이 표시 중 배경 요소 도달 불가 | 화면별 스와이프 전체 순회 |
| **A3** | 시맨틱 컨트롤 | 액션은 `Button`/`Toggle`/`Picker`. **주요 액션의 `.onTapGesture` 0건** (현재 7건) | `grep` + Inspector 트레이트 |
| **A4** | Dynamic Type | xSmall–AX5에서 잘림 없음 · 주 액션 화면 안 · 가로 스크롤 없음 | §7.4 |
| **A5** | AX 우선순위 | AX5에서 §7.3의 5개 요소가 **항상 조작 가능** | AX5에서 각 화면 주 액션 탭 |
| **A6** | 터치 타깃 | 모든 탭 가능 요소 **≥ 44×44pt**, 인접 간격 **≥ 8pt** | Inspector 프레임 실측 |
| **A7** | 명도 대비 | 본문/아이콘 ≥ 4.5:1, 대형 텍스트 ≥ 3:1, **라이트·다크 각각** | Inspector Contrast + 토큰 조합표 |
| **A8** | 색 단독 신호 금지 | 상태를 색만으로 표현하지 않음 (녹음 / 신뢰도 / 타이머 / 현재 플랜) | 그레이스케일 렌더링에서 구분 가능 |
| **A9** | Reduce Motion | 활성 시 장식 애니메이션 제거·크로스페이드 대체. **전환이 상태를 잃지 않음** | On/Off 각 1회 전체 주행 |
| **A10** | 모달 포커스 | 모든 모달에 `.accessibilityAddTraits(.isModal)` + 명시적 닫기 (현재 `.isModal` **0건**) | VoiceOver로 배경 도달 시도 |
| **A11** | 로딩·진행 알림 | 비동기 시작/완료 시 VoiceOver 발표. **로딩 중 버튼이 접근성 이름을 잃지 않음** (현재 `PrimaryButton`이 잃음) | 문제 생성·분석·광고 검증 3경로 |
| **A12** | 타이머 알림 | 180초 타이머가 `accessibilityValue` 제공 + 임계 시점 발표. **색 변화 단독 경고 금지** | 1문항 VoiceOver 완주 |
| **A13** | 라이트/다크 | 11화면 × 2모드 대비·가독성 동등. 하드코딩 색으로 대비 깨짐 **0건** | §8.4 |

**우선순위:** A3 → A4 → A6 → A10 → A7 → A11 → 나머지.
A3·A4는 컴포넌트 설계 시점 결정이므로 **디자인 시스템 단계에서 잠근다.**

# 10. Layout shell

## 10.1 화면 골격

```
┌─────────────────────────────┐
│ Safe area top               │
│ ┌─────────────────────────┐ │
│ │ Navigation bar (inline) │ │  ← 시스템 제공. 커스텀 헤더 금지
│ ├─────────────────────────┤ │
│ │                         │ │
│ │  Scroll content         │ │  ← 좌우 여백 lg(24)
│ │  (bgBase)               │ │
│ │                         │ │
│ ├─────────────────────────┤ │
│ │ Fixed action area       │ │  ← 스크롤되지 않음 (§10.4)
│ └─────────────────────────┘ │
│ Tab bar                     │
│ Safe area bottom            │
└─────────────────────────────┘
```

## 10.2 Safe area

- 모든 콘텐츠는 safe area를 존중한다. 홈 인디케이터·다이나믹 아일랜드 영역에 조작 요소를 두지 않는다.
- 배경색만 safe area를 넘어 확장한다(`.ignoresSafeArea(edges: .bottom)`은 배경 레이어에만).
- **스크롤 콘텐츠 하단에는 고정 액션 영역 높이만큼의 패딩을 확보**해 마지막 항목이 가려지지 않게 한다.

## 10.3 Tab bar

- 3개 유지. 라벨 + SF Symbol 병기(현재도 그러하며 올바르다).
- **커스텀 플로팅 탭바를 만들지 않는다.** 현재 플로팅 탭바가 화면 하단 콘텐츠(특히 배너)를 가리는 것이
  감사에서 확인된 문제다. **시스템 `TabView` 기본 표현으로 되돌린다.**
- 배지는 쓰지 않는다(현재 미사용. 추가하지 않음).

## 10.4 Fixed controls (고정 액션 영역)

**스크롤에서 분리되는 영역.** §7.3의 "AX5에서도 반드시 조작 가능한 요소"가 여기 산다.

| 화면 | 고정 영역 내용 |
|---|---|
| 데일리 | **녹음 버튼 + 현재 상태 라벨** |
| 모의고사(답변 중) | 녹음 버튼 + 남은 시간 |
| 모의고사(게이트) | 계속 / 나중에 / 포기 |
| 결과 | 다음 문항 (또는 다시 말하기) |
| 페이월 | 주 CTA |

- 고정 영역은 **`.regularMaterial` 배경 + 상단 `separator`** 로 스크롤 콘텐츠와 분리한다.
  이것이 iOS 네이티브 하단 액션 바의 표준 표현이다.
- 고정 영역은 **콘텐츠를 가리지 않는다.** §10.2의 하단 패딩 규칙으로 보장한다.

## 10.5 Scroll behavior

- 기본은 `ScrollView` + `.scrollBounceBehavior(.basedOnSize)` — 콘텐츠가 짧을 때 불필요한 바운스 제거.
- **중첩 스크롤 금지.** 스크롤 안에 가로 스크롤 캐러셀을 넣지 않는다.
- 뒤로가기 시 스크롤 위치를 복원한다(A2·§4.3).
- 리스트성 화면(설정·기록)은 `List`를 쓴다. `ScrollView` + 수동 `VStack`으로 리스트를 재현하지 않는다
  (설정은 현재 `List`를 쓰며 올바르다).

## 10.6 Ads placement (Q5 LOCKED 확정 배치)

| 화면 | 배너 | 위치 |
|---|---|---|
| **데일리(말하기 흐름)** | **없음** | Q5 LOCKED — 핵심 발화 흐름에서 제거 |
| **결과** | 있음 | 스크롤 콘텐츠 **최하단**, 고정 액션 영역 **위쪽**, `separator`로 분리 |
| **통계** | 있음 | 스크롤 콘텐츠 최하단 |
| **모의고사 인트로** | 있음 | 스크롤 콘텐츠 최하단 (설문 선택 CTA 아래) |
| 모의고사 답변 중 | 없음 | 현재도 없음. 유지 |
| 설정 · 페이월 · 온보딩 · 가이드 | 없음 | 현재도 없음. 유지 |

**배치 규칙**
1. 배너는 **고정 영역이 아니라 스크롤 콘텐츠의 마지막 요소**다. 절대 화면에 고정하지 않는다.
2. 배너 위에 `separator`와 `lg`(24) 여백을 둬 콘텐츠와 명확히 분리한다. 광고임이 시각적으로 분명해야 한다.
3. **탭바에 가리지 않는다.** 시스템 탭바 복귀(§10.3) + 하단 패딩으로 보장한다.
4. **유료 플랜에서는 높이 자체가 0이다.** 현재는 `BannerAdView`가 `Color.clear`를 반환하는데
   호출부가 `.frame(height: 50)`을 강제해 **50pt 빈 공간이 남는다.**
   → **`BannerAdView`가 자기 높이를 소유**하고, 미노출 시 `EmptyView`를 반환한다.
   "광고 완전 제거"를 구매한 사용자에게 광고 자리가 남아서는 안 된다.

# 11. Navigation / sheet / modal patterns

## 11.1 모달 계약 (전 모달 공통)

모든 모달은 아래를 **예외 없이** 만족한다.

1. `.accessibilityAddTraits(.isModal)` — 현재 앱 전체 **0건**
2. **명시적 닫기 어포던스** — 좌상단 "닫기" 또는 우상단 "완료". 제스처에만 의존하지 않는다
3. 스크림은 `.regularMaterial` **단일 값** (§6.6)
4. 배경 탭으로 닫히는 모달은 **비파괴적인 것만** — 파괴적 결과가 있으면 명시적 확인 필요
5. 미저장 변경이 있으면 닫기 전에 확인한다

**공통 컨테이너 컴포넌트 하나를 만들고 모든 모달이 그것을 경유한다.** 위 5개를 호출부에 맡기면 반드시 샌다.

## 11.2 커스텀 오버레이 → 시스템 컴포넌트 대체

현재 앱은 `ResetMockExamDialog`, `SavedSurveyDialog`, `TargetLevelConfirmationDialog` 등
**커스텀 오버레이 6종**을 쓴다. 접근성·포커스·Reduce Motion을 전부 직접 구현해야 한다.

| 현재 | 대체 | 이득 |
|---|---|---|
| `ResetMockExamDialog` | `.confirmationDialog` | 파괴적 액션 스타일·포커스·VoiceOver 무료 |
| `TargetLevelConfirmationDialog` | `.confirmationDialog` | 동일 |
| `SavedSurveyDialog` | `.confirmationDialog` | 동일 |
| `AILoadingOverlay` | **인라인 상태 + 진행 표시** (§15) | 모달이 아니어야 함 — 취소 가능해야 하므로 |
| `AppLoadingIndicator` | 유지 (인라인 인디케이터) | |

> **원칙: 시스템이 제공하는 것을 다시 만들지 않는다.** 커스텀 다이얼로그는 브랜드 표현이 필요한
> 극히 일부에만 남긴다. 이 앱에는 그런 곳이 없다.

## 11.3 시트 크기

| 용도 | detent |
|---|---|
| 설정 | `.large` |
| 페이월 | `.large` |
| 짧은 선택(있다면) | `.medium` + `.presentationDragIndicator(.visible)` |

## 11.4 fullScreenCover 2종 (§4.1)

온보딩·가이드에만 사용한다. 각각 다음을 갖는다.
- 진행 단계 표시(온보딩)

- 스와이프 다운 이탈 불가 (`fullScreenCover`의 기본 동작)

# 12. Button hierarchy

## 12.1 4단계

| 레벨 | 표현 | 규칙 |
|---|---|---|
| **Primary** | `actionPrimary` 채움 + `actionOnPrimary` 라벨, `control`(12) 라운드 | **화면당 1개** |
| **Secondary** | `surface` 배경 + `textPrimary` 라벨 + `separator` 테두리 | 화면당 최대 2개 |
| **Tertiary** | 라벨만 (`actionPrimary` 색) | 개수 제한 없음 |
| **Destructive** | `danger` 라벨 (Tertiary 형태) 또는 `.confirmationDialog`의 `.destructive` | 항상 확인 경유 |

## 12.2 공통 규칙

- **전부 `Button`이다.** `.onTapGesture`로 만든 액션은 존재하지 않는다(A3).
- 최소 크기 **44×44pt**. 컴포넌트 자체가 `.frame(minHeight: 44)` + `.contentShape`로 보장한다.
- **로딩 중에도 접근성 이름을 유지한다.** 현재 `PrimaryButton`은 로딩 시 라벨을 스피너로 교체해
  이름이 사라진다 → 라벨은 유지하고 스피너를 **덧붙인다**(또는 `.opacity(0)` + `accessibilityLabel` 보존).
- 비활성 상태: `.disabled(true)` + 불투명도 감소. **회색으로만 표현하지 않고** 왜 비활성인지
  근처에 텍스트로 설명한다.
- 파괴적 액션은 주 액션과 **시각적으로 분리**하고 인접 배치하지 않는다.

## 12.3 녹음 버튼 (특수)

녹음 버튼은 위 4단계에 속하지 않는 **단일 목적 컴포넌트**다. §16에서 별도 정의한다.
- 크기: 최소 64×64pt (44pt 기준을 크게 상회 — 이 앱의 주 행동)
- 화면당 정확히 1개
- 위치: 고정 액션 영역(§10.4)

# 13. Card hierarchy

## 13.1 카드를 쓰지 않는 기본값

**카드는 기본이 아니라 예외다.** 관련 콘텐츠를 묶는 1순위 도구는 **여백**, 2순위는 **구분선**,
3순위가 카드다. 현재 앱의 "카드 남발"은 그룹핑 도구 선택 실패다.

## 13.2 카드를 쓰는 조건 (전부 만족할 때만)

1. 내용이 **독립적으로 의미를 갖는 단위**다 (예: 하나의 문항, 하나의 결과)
2. 같은 계층의 형제가 **2개 이상** 존재한다
3. 탭 가능하거나, 시각적 경계 없이는 인접 콘텐츠와 혼동된다

## 13.3 카드 스펙

| 속성 | 값 |
|---|---|
| 배경 | `surface` |
| 라운드 | `card`(16), `.continuous` |
| 내부 패딩 | `md`(16) |
| 카드 간 간격 | `md`(16) |
| 그림자 | **없음** |
| 테두리 | 없음 (배경 대비로 충분). 대비 부족 시에만 `separator` 1px |

## 13.4 카드 중첩 금지

**카드 안에 카드를 넣지 않는다.** 중첩이 필요하다고 느껴지면 바깥을 섹션(여백 + 헤더)으로 바꾼다.

## 13.5 정보 밀도

카드 하나에 담는 정보는 **제목 + 본문 + 최대 1개의 메타 라인**. 그 이상은 상세 화면으로 밀어낸다.

# 14. Chips / tags / question navigation

## 14.1 문항 네비게이션 (데일리 · 14문항)

현재 진행바 칩은 22–24pt로 **44pt 터치 타깃 기준에 미달**한다(A6 실패). 이것이 이 컴포넌트의 P0다.

### 스펙

| 속성 | 값 |
|---|---|
| 터치 타깃 | **44×44pt 이상** (시각 크기가 작아도 `contentShape`로 확장) |
| 칩 간 간격 | `sm`(8) |
| 배치 | 가로 스크롤 (14개) |
| 컨트롤 | `Button` (A3) |

### 상태 표현 (색 단독 금지 — A8)

| 상태 | 표현 |
|---|---|
| 현재 문항 | `actionPrimary` 채움 + `actionOnPrimary` 숫자 + **테두리 강조** |
| 분석 완료 | `successSoft` 배경 + **체크 아이콘** + 숫자 |
| 미답변 | `surface` 배경 + `textSecondary` 숫자 |
| 신뢰 낮음(B) | `surface` 배경 + **경고 아이콘** + 숫자 |

각 칩의 VoiceOver 라벨: `"3번 문항, 분석 완료"` / `"7번 문항, 아직 답하지 않음"`.

### 이 컴포넌트가 전달해야 하는 핵심 메시지

> **"이 세트 안에서는 몇 번이든 다시 말할 수 있다."** (Q3 LOCKED)

분석 완료된 문항도 **다시 선택 가능**해야 하며, 재선택 시 "다시 말하기"가 자연스러운 행동으로
보여야 한다. 완료 = 잠김이 아니다.

## 14.2 태그 (읽기 전용 메타)

문항 유형·주제 등 **정보 전달만 하는 태그**는 탭 불가하며 시각적으로 칩과 구분한다.
- 배경 없음 또는 `surface`, `caption` 타이포, `textSecondary`
- 탭 가능해 보이지 않게 한다 (라운드를 약하게, 채움 없이)

## 14.3 선택 칩 (설문 · 목표 등급)

온보딩의 배경 설문·목표 등급 선택에 사용.
- **`Button` 기반, 44pt 이상, 단일/다중 선택 여부를 시각적으로 구분**
- 선택됨: `actionPrimarySoft` 배경 + `actionPrimary` 라벨 + 체크 아이콘
- VoiceOver: `.accessibilityAddTraits(.isSelected)`

# 15. Loading / empty / error patterns

## 15.1 로딩 3종

| 유형 | 조건 | 표현 |
|---|---|---|
| **인라인 스피너** | < 1초 예상, 국소적 | 해당 요소 자리에 `ProgressView()` |
| **스켈레톤** | > 1초 예상, 구조를 아는 콘텐츠 | 최종 레이아웃과 동일한 형태의 placeholder |
| **전면 진행 상태** | AI 분석 등 수 초 이상 | **모달 아닌 인라인 상태.** 진행 단계 텍스트 + 취소 가능 시 취소 |

**규칙**
- 로딩 중에도 **레이아웃이 흔들리지 않는다.** 자리를 미리 확보한다.
- 300ms 미만으로 끝나는 작업에는 로딩 표시를 하지 않는다(깜빡임이 더 나쁘다).
- **VoiceOver 발표 필수**(A11): 시작 시 `"분석하고 있어요"`, 완료 시 결과 요약.
- 진행 단계 텍스트는 **실제 단계를 반영**한다. 현재 `OnboardingView`의 광고 로딩 3단계
  ("잠시만요, 준비하고 있어요" → "광고를 불러오고 있어요" → "광고 시청을 확인하고 있어요")는
  실제 단계와 일치하는 좋은 사례다. 이 패턴을 다른 곳에도 적용한다.

## 15.2 빈 상태

빈 상태는 **오류가 아니라 시작점**이다. 항상 다음 3요소를 갖는다.

1. **무엇이 없는지** (한 줄, 중립적 톤)
2. **왜 없는지** (필요할 때만)
3. **다음 행동** (Primary 버튼 1개)

| 화면 | 빈 상태 문구 방향 |
|---|---|
| 통계 (기록 없음) | "아직 학습 기록이 없어요" + [데일리 시작하기] |
| 취약 유형 (데이터 부족) | "분석할 답변이 더 필요해요" + 필요 조건 안내 |
| 모의고사 기록 없음 | "아직 모의고사를 보지 않았어요" + [모의고사 시작] |

> **일러스트를 넣지 않는다.** 아이콘 하나 + 텍스트로 충분하다(calm).

## 15.3 오류 상태

**모든 오류는 원인 + 복구 경로를 함께 제시한다.** "다시 시도해 주세요"만 있는 오류는 금지한다.

| 오류 유형 | 표현 | 복구 경로 |
|---|---|---|
| 네트워크 | 인라인 배너 (화면 상단) | [다시 시도] |
| 권한 거부(마이크·음성) | **전용 화면** (§20.4) | [설정 열기] 딥링크 |
| 쿼터 소진 | **오류가 아님.** 선택지 화면(§19.4) | [광고 보고 1세트 더] / [업그레이드] |
| 서버 세션 불일치 | 인라인 + 상태 복구 | [이어서 하기] / [포기하기] — **둘 다 항상 존재** |
| AI 분석 실패 | 인라인 | [다시 분석] — **재녹음 없이 재시도**(토큰 미소모) |
| 광고 로드 실패 | 게이트 화면 인라인 | [다시 시도] / [나중에] / [포기] |

**오류 표시 위치**
- 필드/요소와 관련된 오류는 **그 요소 바로 아래**
- 화면 전체에 해당하는 오류는 **상단 인라인 배너** (토스트로 흘려보내지 않는다)
- **`role: .alert` 상당의 VoiceOver 발표**를 동반한다

## 15.4 절대 만들지 않는 상태

- 탈출구 없는 오류 화면 (P4 위반)
- "다시 시도"를 눌러도 같은 실패가 반복되는 상태 (현재 모의고사 데드엔드)
- 원인을 말하지 않는 실패 (현재 인터럽션 시 조용한 초기화)

# 16. Speaking state machine UI

**이 앱에서 가장 중요한 섹션이다.** 현재 앱은 8개 상태를 `speech.isListening`(Bool) 하나로 붕괴시킨다.

## 16.1 상태 다이어그램

```
                    ┌──────────────────────────────────────┐
                    │                                      │
   ready ──탭──▶ recording ──종료(수동/180초)──▶ finishing  │
     ▲               │                              │      │
     │               │ 인터럽션(.began)             ▼      │
     │               ▼                          processing │
     │          interrupted                         │      │
     │            │    │                            │ 전사 확정
     │  이어서 ───┘    └─ 버리기 ──▶ ready          ▼      │
     │                                    ┌──────────────┐ │
     │                                    │ 답변 확인    │ │
     │                                    │ [다시 녹음]──┼─┘
     │                                    │ [분석하기]   │
     │                                    └──────┬───────┘
     │                                           ▼
     │                                       analyzing
     │                                           │
     │                          ┌────────────────┴────────┐
     │                          ▼                         ▼
     │                       result                     error
     └──── 다시 말하기 ─────────┴────── 다시 분석 ─────────┘
```

> **주의:** 사용자가 확정한 8상태는 `ready / recording / finishing / processing / analyzing /
> result / interrupted / error`다. 위 "답변 확인"은 **새로운 상태가 아니라 `processing`이
> 전사를 확정한 뒤의 표현**이다(Q1 LOCKED의 "전사 확인 후 재녹음" 요구를 만족).

## 16.2 상태별 UI 사양

### `ready`

| 항목 | 내용 |
|---|---|
| 녹음 버튼 | `actionPrimary` 채움, 마이크 아이콘, 64pt+ |
| 상태 라벨 | "탭해서 말하기 시작" |
| 부가 표시 | 최대 시간 안내 ("최대 3분") |
| VoiceOver | label "말하기 시작", hint "탭하면 녹음이 시작됩니다. 최대 3분" |
| 진입 조건 | 마이크·음성 인식 권한 허용됨 |

> 권한이 거부된 경우는 `ready`가 아니라 **권한 전용 화면**(§20.4)이다.

### `recording`

| 항목 | 내용 |
|---|---|
| 녹음 버튼 | `recording`(systemRed) 채움, 정지 아이콘 |
| 상태 라벨 | **"듣고 있어요"** |
| 필수 표시 | **경과/남은 시간** (`.monospacedDigit()`), 실시간 부분 전사 |
| 시각 신호 | 은은한 펄스 (Reduce Motion 시 정적 링으로 대체 — 현재 `RecordingButton`이 이미 대응) |
| VoiceOver | label "녹음 중지", value "남은 시간 2분 14초" |
| 종료 | 수동 탭 / 180초 도달 |

**금지:** 파형 시각화. 실제 오디오 레벨을 표시하지 않으면서 파형처럼 보이는 장식은 fake precision이다.
표시한다면 실제 `AVAudioEngine` 탭의 레벨을 써야 한다 — 현재 구현에 없으므로 **이번 범위 밖**.

### `finishing`

| 항목 | 내용 |
|---|---|
| 녹음 버튼 | 비활성 + 인라인 스피너 |
| 상태 라벨 | **"마무리하고 있어요"** |
| 지속 | 짧음 (현재 코드의 250ms 정착 구간 + STT 최종 결과 대기) |
| VoiceOver | 발표 "녹음을 마무리하고 있어요" |

이 상태는 짧지만 **반드시 존재해야 한다.** 현재는 이 구간이 보이지 않아 사용자가 버튼을 다시 누른다.

### `processing`

| 항목 | 내용 |
|---|---|
| 초기 표현 | "답변을 정리하고 있어요" + 스피너 (m4a 압축 구간) |
| **확정 후 표현** | **답변 확인 카드** |

**답변 확인 카드 (Q1 LOCKED 핵심)**

```
┌──────────────────────────────────┐
│ 내가 말한 내용                    │
│                                  │
│ "I usually go to the park on..." │  ← 전사 전문. 스크롤 가능
│                                  │
│ 45초 · 82단어                     │  ← 실제 측정값만 표시
├──────────────────────────────────┤
│ [다시 녹음]        [분석하기]     │  ← Secondary / Primary
└──────────────────────────────────┘
```

- **"다시 녹음"은 아무 비용이 없다는 것을 명시한다** — "다시 말해도 토큰이 줄지 않아요" (Q3 LOCKED)
- 표시하는 수치는 **실제 측정된 것만**. 서버 `AudioMetrics`가 추정 폴백일 수 있으므로(T4),
  클라이언트가 직접 아는 값(녹음 길이·전사 단어 수)만 이 시점에 표시한다.
- 전사가 비어 있으면 이 카드가 아니라 **C 버킷 처리**(§18)로 직행한다.

### `analyzing`

| 항목 | 내용 |
|---|---|
| 표현 | 인라인 진행 상태 (**모달 아님**) |
| 상태 라벨 | "AI가 분석하고 있어요" |
| 진행 표시 | 부정형 `ProgressView` (가짜 퍼센트 금지) |
| 이탈 | 화면을 벗어나도 분석은 계속되고, 돌아오면 결과 또는 진행 상태 (P3) |
| VoiceOver | 시작·완료 발표 (A11) |

**금지:** "분석 73% 완료" 같은 가짜 진행률. 서버가 진행률을 제공하지 않는다.

### `result`

§21에서 상세 정의. A/B/C 3분기(§18).

### `interrupted`

| 항목 | 내용 |
|---|---|
| 표현 | **오류가 아닌 복구 가능 상태**로 디자인 |
| 상태 라벨 | "통화나 다른 오디오로 녹음이 멈췄어요" |
| 액션 | **[이어서 녹음]** (Primary) / [버리고 다시] (Secondary) |
| **오디오** | **보존한다** (현재는 `cancel()`이 삭제 — R4 위반) |
| VoiceOver | 발표 필수. 현재는 조용히 사라져 원인을 알 수 없다 |

**현재 코드의 두 가지 문제 (§17.4에서 상세)**
1. `AVAudioSessionInterruptionType`(`.began`/`.ended`)을 읽지 않아 종료 알림에도 동일 반응
2. `interruptionReason` 문자열의 **소비처가 앱 전체에 0곳**

### `error`

| 항목 | 내용 |
|---|---|
| 표현 | 인라인 (§15.3) |
| 내용 | 원인 + 복구 액션 |
| 액션 | 분석 실패 → [다시 분석] (**재녹음 불필요, 토큰 미소모**) / 녹음 실패 → [다시 녹음] |

## 16.3 상태 전이 시 공통 규칙

- **모든 상태 전이는 VoiceOver로 발표된다**(A11).
- 상태 라벨은 **버튼 안이 아니라 버튼 근처**에 별도 텍스트로 존재한다. 버튼 아이콘 변화만으로
  상태를 전달하지 않는다(A8).
- 전이 애니메이션은 **150–250ms 크로스페이드**. Reduce Motion 시 즉시 전환(A9).
- 어떤 상태에서도 **화면을 벗어날 수 있다**(P3·P4). 벗어나면 §5 규칙에 따라 보존된다.

# 17. Recording termination UX

**Q1 LOCKED 확정 정책을 UI로 구체화한다.**

## 17.1 확정 정책

| 트리거 | 동작 |
|---|---|
| **수동 종료** | `recording` → `finishing`. 사용자 의도가 항상 최우선 |
| **180초 도달** | 자동 `finishing` + **명시적 안내** |
| **무음 지속** | **자동 종료하지 않는다.** 아무 동작 없음 |
| **인터럽션 `.began`** | `interrupted` + **오디오 보존** |
| **인터럽션 `.ended`** | "이어서 녹음" 제안 |

## 17.2 시간 표시 규칙

- **경과가 아니라 남은 시간**을 주로 표시한다. `.monospacedDigit()` 필수.
- 임계 시점에 **시각 + VoiceOver 양쪽으로** 알린다(A12).
  - 60초 / 30초 / 10초 남음 시 VoiceOver 발표
  - 시각적으로는 남은 시간 텍스트의 굵기·색 변화 — **색만으로 알리지 않는다**(A8)
- 180초 도달 시: 자동 종료 후 **"제한 시간에 도달해 녹음을 마쳤어요"** 를 명시.
  사용자가 "왜 갑자기 멈췄지?"라고 느끼면 실패다.

## 17.3 종료와 제출의 분리 (정책의 핵심)

```
현재:  [정지] ──▶ 즉시 서버 전송 + 분석 시작     ← 되돌릴 수 없음
확정:  [종료] ──▶ 전사 확인 ──▶ [분석하기]      ← 되돌릴 수 있음
                      └──▶ [다시 녹음]
```

**이 정책이 가능한 이유:** 세트 내 평가가 무제한이므로(Q3 LOCKED) 재녹음·재분석에 **추가 비용이 0**이다.
UI는 이 사실을 답변 확인 카드에서 명시적으로 알린다.

## 17.4 인터럽션 처리 (R4)

| 항목 | 현재 | 확정 |
|---|---|---|
| 인터럽션 타입 구분 | 없음 (`.began`/`.ended` 동일 처리) | **구분한다** |
| 오디오 파일 | `cancel()`이 **삭제** | **보존** |
| 전사 | 초기화 | **보존** |
| 사용자 안내 | `interruptionReason` 생성하지만 **읽는 곳 0** | `interrupted` 상태 UI로 표시 |
| 복구 | 없음 | [이어서 녹음] / [버리고 다시] |

## 17.5 STT 조용한 종료 (알려진 한계)

`SFSpeechAudioBufferRecognitionRequest`는 무음이 길어지면 자체적으로 `isFinal`을 내고 태스크를 끝낸다.
그 이후 오디오는 계속 파일에 기록되지만 **전사는 더 이상 늘지 않는다.**

- 현재 이 상황을 감지하는 코드도, 알리는 UI도 없다.
- **이번 범위:** `processing`의 답변 확인 카드에서 전사와 녹음 길이를 함께 보여주므로,
  사용자가 "말한 것보다 전사가 짧다"를 스스로 확인하고 다시 녹음할 수 있다.
- **범위 밖:** STT 조기 종료의 자동 감지·재시작. 별도 구현 과제로 기록한다.

# 18. Low-confidence / invalid-answer UX

**Q2 LOCKED — A/B/C 3버킷. 임계값은 이 문서에서 정하지 않는다.**

## 18.1 확정 제약 (다시 명시)

> 1. **`DESIGN.md` 단계에서 임의의 단어 수·WPM·무음 비율 임계값을 만들어내지 않는다.**
> 2. 임계값은 구현 단계에서 실제 backend signal과 테스트 케이스를 근거로 별도 확정한다.
> 3. **B/C 상태에서는 근거 없이 높은 예상 등급을 보여주지 않는다.**

이 섹션은 **버킷별 UI 표현**만 정의한다. 분류 규칙은 정의하지 않는다.

## 18.2 버킷별 UI

### A. 평가 가능

정상 결과. §21의 전체 결과 화면을 그대로 표시한다.

- 예상 등급 + 5차원 루브릭 + 강점/개선점 (+ 플랜에 따라 교정·모범답안)
- 등급 추이 통계에 **집계된다**

### B. 신뢰 낮음

**등급을 보여주되 "참고치"로 강등한다.**

```
┌──────────────────────────────────────┐
│ ⚠︎  이 답변은 정확히 평가하기 어려워요 │
│                                      │
│    답변이 짧아 예상 등급의 정확도가    │
│    낮습니다.                          │
│                                      │
│    참고 예상 등급   IL               │  ← 시각적으로 약하게
│                                      │
│    [다시 말해보기]                    │  ← Primary
└──────────────────────────────────────┘
```

**규칙**
- 등급 배지를 **A 버킷보다 시각적으로 약하게** 표현한다 (크기·굵기·채움 없음)
- **"참고"라는 단어를 반드시 붙인다.** "예상 등급 IL"이 아니라 "참고 예상 등급 IL"
- 낮은 이유를 **구체적으로** 말한다 — 서버가 실제로 계산한 신호에 근거해서만
  (예: "답변이 짧아요" / "말한 시간이 짧아요"). **근거 없는 일반론 금지**
- **등급 추이 통계에서 제외한다.** 통계 화면에서 제외 사실을 각주로 표시
- 5차원 루브릭은 표시하되 동일하게 "참고" 맥락 안에 둔다
- **Primary 액션은 "다시 말해보기"** — 결과 소비가 아니라 재시도를 유도한다
- 톤은 **실패 통보가 아니라 코칭**: "더 길게 말하면 더 정확히 분석할 수 있어요"

### C. 평가 불가 · 다시 말하기 필요

**등급을 아예 표시하지 않는다.**

```
┌──────────────────────────────────────┐
│ 🎤  답변을 다시 들려주세요             │
│                                      │
│    답변이 너무 짧아 분석할 수 없어요.  │
│                                      │
│    질문을 다시 읽고, 문장으로          │
│    답해보세요.                        │
│                                      │
│    [다시 말하기]                      │  ← Primary
│    [질문 다시 보기]                   │  ← Secondary
└──────────────────────────────────────┘
```

**규칙**
- **예상 등급·루브릭·점수를 일절 표시하지 않는다** (Q2 제약 3)
- **학습 기록에 저장하지 않는다.** 통계에도 반영하지 않는다
- **토큰/쿼터를 소모하지 않는다** (Q3 LOCKED — 이미 발급된 세트 내이므로 자동 충족)
- 가능하면 **AI 호출 전에 차단**한다 (비용 절감. 현재는 3단어 답변에도 정상 요금 발생)
- 톤은 **비난이 아니라 안내**. "잘못했다"가 아니라 "다시 들려주세요"

## 18.3 5차원 루브릭 표시 (fake precision 제거)

**서버는 5단계 밴드로 계산한다.** `foundation / developing / functional / strong / advanced`.
현재 이것을 `20 / 40 / 60 / 80 / 95` 숫자로 변환해 표시한다.

> 통계 화면에서 모든 항목이 "20"으로 보였던 것은 계산 오류가 아니라
> **전 차원이 `foundation` 밴드였기 때문**이다.

**확정: 숫자를 표시하지 않고 밴드 라벨로 표시한다.**

```
발음·전달        ●●○○○  기초
어휘             ●●●○○  발전 중
문법 정확도      ●●○○○  기초
내용 구성        ●●●○○  발전 중
과제 수행        ●●●●○  안정적
```

- 5단계 이산 스케일임이 시각적으로 드러나야 한다 (연속 막대·레이더 차트 금지)
- 라벨 텍스트를 **반드시 병기**한다 (A8 — 점 개수만으로 전달 금지)
- 밴드 이름은 학습자 언어로 번역하되 **5단계를 유지**한다
- VoiceOver: `"어휘, 5단계 중 3단계, 발전 중"`

**금지:** 100점 만점 점수, 소수점, 퍼센트, 백분위, 레이더 차트.
서버가 모르는 정밀도를 UI가 만들어내지 않는다(P2).

## 18.4 disclaimer

서버가 내려주는 `disclaimer`("학습용 AI 예상치")를 **모든 결과 화면에 계속 노출한다.**
작게 표시하되 숨기지 않는다.

## 21.2 표시 규칙

- **예상 등급 옆에는 항상 신뢰 상태가 있다** (A: 표시 없음 또는 체크 / B: 경고 + "참고" / C: 등급 없음).
- `disclaimer`는 등급 바로 아래. 숨기지 않는다.
- 오디오 지표(초·단어·WPM)는 **서버가 실제로 측정한 경우에만** 표시한다.
  서버가 추정 폴백을 썼는지 구분할 수 있는 필드(`isEstimated`)가 **현재 없다**
  → **이 필드가 추가되기 전까지 WPM·무음 비율은 표시하지 않는다.** 녹음 길이와 단어 수는
  클라이언트가 직접 아는 값이므로 표시 가능하다.
- **"다시 말하기"는 항상 존재한다.** 세트 내 재평가가 무제한이므로(Q3 LOCKED) 이 버튼에
  비용 경고를 붙이지 않는다.

## 21.3 플랜에 따라 없는 항목 처리

서버는 `analysis_depth`가 `summary`/`basic`이면 `correctedAnswer` / `sampleAnswer` / `targetGap`을
**아예 생성하지 않는다**(`ai.py`). 이것은 **실제로 강제되는 유일한 유료 차별화**다.

- 해당 항목이 `nil`이면 **빈 카드를 그리지 않는다.**
- 대신 섹션 위치에 **한 줄 업셀**을 둔다: "교정된 답변과 모범 답안은 플러스 플랜부터 제공돼요" + [플랜 보기]
- **잠금 아이콘으로 도배하지 않는다.** 한 곳에 한 번만.

## 21.4 B / C 버킷

§18.2의 전용 표현으로 대체한다. A 버킷 레이아웃을 재사용하되 등급 영역만 바꾸는 방식이 **아니다** —
특히 C는 별도 화면이다.

## 21.5 부분 결과 (`resultStatus == "partial"`)

서버는 경고가 있으면 `resultStatus`를 `partial`로 내린다. 이 경우 결과 상단에
**"일부 항목을 분석하지 못했어요"** 를 표시하고 누락 항목을 빈 값으로 두지 않는다.

## 22.2 광고 게이트 화면 (3개 공통 사양)

```

│  모의고사를 시작할게요        │
│                             │
```

  **알려진 카피 버그**를 여기서 함께 정리한다.
- 광고 상태 4단계를 표시한다(§15.1): 불러오는 중 / 시청 중 / 확인 중 / 실패.
  `AdService.State`에 이미 `loading/presenting/verifying/failed`가 있으나 UI가 쓰지 않는다.
- **실패 시 nonce를 버리지 않는다**(Q4 LOCKED). "다시 시도"가 광고를 다시 보게 만들지 않는다.

## 22.3 진행 표시

문항 번호(n/15)가 아니라 **단계**로 표현한다. 실제 상태 머신과 일치시킨다.

```
시작 ──▶ 앞 7문항 ──▶ 난이도 조정 ──▶ 뒤 8문항 ──▶ 결과
        ●●●●○○○
```

## 22.4 답변 화면

- 데일리와 **동일한 말하기 상태 머신**(§16)을 쓴다. 단 아래가 다르다.
  - 180초 타이머가 **필수 표시**된다 (데일리는 정보성)
  - **뒤로가기 없음** — `previousQuestion()`은 현재 빈 함수이며, 실전 OPIc과 일치하므로 유지
  - 답변 확인 카드(§16.2)는 **표시하되 "다시 녹음"은 남은 시간 안에서만** 가능
- 배너 광고 없음 (현재도 없음. 유지)

- → **구현 단계에서 명시적 매핑 테이블로 교체한다.** 서버와 동일한 키 집합을 클라이언트에도 둔다.

## 26.4 UI 규칙

- 구매 중에는 **해당 버튼만 로딩**하고 다른 플랜은 비활성화한다(현재 불투명도로 처리 중 — 유지하되
  `.disabled()`를 함께 적용해 접근성에도 반영).
- 구매 성공 시 **명시적 확인**을 보여준다. 조용히 페이월이 닫히지 않는다.
- 복원 결과를 항상 알린다 — 복원할 것이 없으면 "복원할 구독이 없어요"까지 말한다.

# 27. Advertising rules

**Q4·Q5 LOCKED. 광고 정책 자체는 변경하지 않는다. 표현과 전달만 정리한다.**

## 27.1 배너

§10.6 확정 배치. 요약:

| 화면 | 배너 |
|---|---|
| 데일리 (말하기 흐름) | **없음** |
| 결과 · 통계 · 모의고사 인트로 | 스크롤 콘텐츠 최하단 |
| 그 외 전부 | 없음 |

**유료 플랜에서는 높이가 0이다.** `BannerAdView`가 자기 높이를 소유하고 미노출 시 `EmptyView`.

## 27.2 리워드 광고 (5개 트리거 · 변경 없음)

| 용도 | 트리거 | 무료 | 유료 |
|---|---|---|---|
| `mock_start` | 모의고사 시작 | 광고 1편 | 즉시(auto-verify) |
| `mock_adjustment` | 난이도 조정 | 광고 1편 | 즉시 |
| `mock_result` | 결과 확인 | 광고 1편 | 즉시 |
| `target_level_change` | 목표 등급 변경 | 광고 1편 | 즉시 |
| `practice_credits` | 데일리 보너스 세트 | 광고 1편 | **불가 → 페이월** |

- `practice_refresh`는 **클라이언트 호출부가 0건**이다. UI에 노출하지 않는다.
- 무료 모의고사 예산은 **하루 3개 유지**(Q4 LOCKED). 상한을 바꾸지 않는다.

## 27.3 리워드 광고 UX 규칙

1. **사전 고지** — 게이트 진입 전 "광고 1편을 보면 시작됩니다 · 3편 중 1번째"
2. **4단계 상태 표시** — 불러오는 중 / 시청 중 / 확인 중 / 실패 (§15.1)
3. **실패 시 nonce 재사용** — "다시 시도"가 광고를 다시 보게 만들지 않는다 (Q4 LOCKED)
4. **유료 문구 분기** — "광고 없이 바로 진행됩니다"
5. **취소 가능** — 광고 로딩 중 취소할 수 있고, 취소해도 예산이 소모되지 않는다

## 27.4 동의 · 추적 (ATT)

**현재: 앱 최초 실행 스플래시에서 UMP 동의 → ATT 요청 → MobileAds 시작.**

- 사용자가 앱의 가치를 보기 전에 추적 허용을 묻는다.
- → **ATT 요청 시점을 첫 광고 노출 직전으로 옮긴다.** 정책 변경이 아니라 **타이밍 조정**이다.
- UMP 동의는 유지(법적 요구). `canRequestAds`가 false면 배너·리워드 모두 표시하지 않는다.

## 27.5 금지

- 말하기 중 광고 표시
- 결과를 보기 위한 전면 광고 (현재도 없음. 추가하지 않음)
- 광고임이 불분명한 배치 (§10.6 규칙 2)
- 유료 사용자에게 광고 자리 남기기

# 28. Motion principles

## 28.1 원칙

**모션은 인과관계를 설명할 때만 존재한다.** 장식용 애니메이션을 만들지 않는다.

## 28.2 허용되는 모션 (4종)

| 종류 | 지속 | 이징 | 용도 |
|---|---|---|---|
| 상태 전환 | 150–250ms | `easeOut` | 말하기 8상태 전환 |
| 화면 전환 | 시스템 기본 | 시스템 기본 | push/sheet/cover — **커스텀하지 않는다** |
| 녹음 펄스 | 반복 | `easeInOut` | `recording` 상태 표시 (의미 있음) |
| 값 변경 | 200ms | `easeOut` | 진행도·남은 세트 수 변화 |

## 28.3 금지

- 스플래시 장식 애니메이션 (부팅을 느리게 보이게 한다)
- 카드 등장 stagger
- 패럴랙스
- 스크롤 연동 애니메이션
- `width`/`height` 애니메이션 (레이아웃 리플로우)
- 500ms 초과 전환

## 28.4 Reduce Motion (A9)

`@Environment(\.accessibilityReduceMotion)` 활성 시:
- 녹음 펄스 → **정적 링**
- 상태 전환 → **즉시 전환** 또는 크로스페이드
- 값 변경 애니메이션 → 즉시

**중요: Reduce Motion에서도 상태 정보가 사라지지 않는다.** 펄스가 없어도 "듣고 있어요" 라벨과
빨간 채움으로 녹음 중임을 알 수 있어야 한다.

현재 4개 파일(`OPIcGuideView`, `AILoadingOverlay`, `RecordingButton`, `AppLoadingIndicator`)이
이미 대응 중이다. 신규 상태에도 확장한다.

## 28.5 인터럽터블

**진행 중 애니메이션이 사용자 입력을 막지 않는다.** 탭하면 즉시 반응한다.

# 29. VoiceOver behavior

## 29.1 화면별 읽기 순서

| 화면 | 순서 |
|---|---|
| 데일리 홈 | 오늘의 상태 → 현재 문항 → 문항 칩 → **말하기 상태 → 녹음 버튼** |
| 결과 | **신뢰 상태 → 예상 등급 → disclaimer** → 5차원 → 강점 → 개선점 → 내 답변 → 액션 |
| 모의고사 게이트 | 단계 안내 → 광고 예산 → 계속 → 나중에 → 포기 |
| 페이월 | 현재 플랜 → 추천 플랜 + CTA → 비교표 → 복원·약관 |

**결과 화면에서 신뢰 상태가 등급보다 먼저 읽힌다.** B 버킷에서 "참고치"라는 맥락 없이
등급만 먼저 들리면 안 된다(P2).

## 29.2 필수 발표 (Announcement)

| 시점 | 발표 |
|---|---|
| 녹음 시작 | "녹음을 시작했어요" |
| 60/30/10초 남음 | "1분 남았어요" 등 |
| 180초 자동 종료 | "제한 시간에 도달해 녹음을 마쳤어요" |
| 인터럽션 | "다른 오디오로 녹음이 멈췄어요" |
| 분석 시작 | "분석하고 있어요" |
| 분석 완료 | "분석이 끝났어요. 참고 예상 등급 IL" (버킷에 따라 문구 변경) |
| 광고 검증 완료 | "확인됐어요. 시작합니다" |
| 오류 | 원인 + 복구 방법 |

현재 앱의 `AccessibilityNotification` 사용은 **0건**이다.

## 29.3 라벨 작성 규칙

- **label = 무엇인가**, **value = 현재 상태**, **hint = 하면 어떻게 되는가**
- 아이콘 전용 버튼은 label 필수
- 복합 정보는 `.accessibilityElement(children: .combine)`으로 하나로 묶는다
  (현재 `DailyTokenBadge`가 이 패턴을 쓰며 올바르다 — 라벨 문구만 §3.3에 맞춰 교체)
- 장식용 이미지는 `.accessibilityHidden(true)`

## 29.4 모달 (A10)

모든 모달에 `.accessibilityAddTraits(.isModal)`. §11.1 공통 컨테이너가 보장한다.

## 29.5 로딩 중 이름 보존 (A11)

`PrimaryButton`이 로딩 시 라벨을 스피너로 교체해 **접근성 이름이 사라진다.**
→ 라벨을 유지하고 스피너를 덧붙이거나, `.accessibilityLabel`을 명시적으로 보존한다.

# 30. Touch target rules

## 30.1 절대 규칙

| 규칙 | 값 |
|---|---|
| 최소 터치 타깃 | **44 × 44 pt** |
| 인접 타깃 간 최소 간격 | **8 pt** (`sm`) |
| 녹음 버튼 | **64 pt 이상** (주 행동) |

## 30.2 컴포넌트가 책임진다

호출부에 맡기지 않는다. 탭 가능한 컴포넌트는 **자기 안에서** 보장한다.

```swift
.frame(minWidth: 44, minHeight: 44)
.contentShape(Rectangle())
```

시각적 크기가 44pt보다 작아도 무방하다 — **히트 영역이 44pt면 된다.**
문항 칩(현재 22–24pt)이 대표 사례다.

## 30.3 현재 위반 (수정 대상)

| 요소 | 현재 | 조치 |
|---|---|---|
| 데일리 문항 칩 | 22–24pt | `contentShape`로 44pt 확장 |
| 툴바 버튼 일부 | 확인 필요 | Inspector 실측 후 조정 |
| 페이월 카드 | `onTapGesture` | `Button` 전환 시 자동 해결 |

## 30.4 안전 영역

주 조작 요소를 노치·다이나믹 아일랜드·홈 인디케이터 영역에 두지 않는다(§10.2).

# 31. Anti-patterns

**이번 리뉴얼에서 명시적으로 금지한다.**

## 31.1 시각

| 금지 | 이유 |
|---|---|
| Generic AI SaaS 대시보드 | 학습 앱이지 분석 도구가 아니다 |
| 과도한 glass / `.ultraThinMaterial` 남용 | Material은 "뒤가 비활성"의 신호일 때만(§6.6) |
| 그라디언트 배경·버튼 | calm에 반한다. 단색 + 위계로 충분 |
| 카드 남발 | 그룹핑 1순위는 여백, 2순위는 구분선(§13.1) |
| 장식용 shadow | 이 앱에 그림자는 없다(§6.6) |
| 카드 중첩 | §13.4 |
| 일러스트 빈 상태 | 아이콘 + 텍스트로 충분 |
| 다크 모드 = 색 반전 | 모드별 톤을 따로 정의(§8.1) |

## 31.2 데이터 표현 (가장 중요)

| 금지 | 이유 |
|---|---|
| **100점 만점 점수 표시** | 서버는 5단계 밴드로 계산한다(§18.3) |
| **가짜 진행률 퍼센트** | 서버가 진행률을 제공하지 않는다 |
| **레이더 차트** | 5개 이산 밴드를 연속 면적으로 왜곡 |
| **점 2개로 추세선** | §23.2 |
| **근거 없는 신뢰도 표시** | `confidence`는 현재 LLM 자유 서술 필드다(P2) |
| **B/C 버킷에서 등급 강조** | Q2 LOCKED 제약 3 |
| **실제 오디오 레벨 없는 파형** | fake precision |
| **추정 폴백 값을 측정값처럼 표시** | `isEstimated` 필드가 생기기 전까지 WPM 미표시(§21.2) |

## 31.3 인터랙션

| 금지 | 이유 |
|---|---|
| `.onTapGesture`로 만든 액션 | A3 |
| 색만으로 상태 전달 | A8 |
| 커스텀 다이얼로그 (시스템 대체 가능한 경우) | §11.2 |
| 커스텀 플로팅 탭바 | §10.3 — 콘텐츠를 가린다 |
| 자동 사라지는 오류 토스트 | 오류는 사용자가 읽을 때까지 남는다 |
| 탈출구 없는 화면 | P4 |
| 정지 = 즉시 제출 | Q1 LOCKED |

## 31.4 SwiftUI에 웹 패턴 이식 금지

| 금지 | 대신 |
|---|---|
| `ScrollView` + `VStack`으로 리스트 재현 | `List` |
| 커스텀 헤더/네비게이션 바 | `NavigationStack` + `.toolbar` |
| 커스텀 모달 오버레이 | `.sheet` / `.fullScreenCover` / `.confirmationDialog` |
| 픽셀 브레이크포인트 분기 | `dynamicTypeSize.isAccessibilitySize` / `ViewThatFits` |
| 웹 그림자 스케일(elevation 1–24) | iOS 레이어링 3단계(§6.6) |
| CSS 트랜지션 감성의 커스텀 전환 | 시스템 전환 |

## 31.5 카피

| 금지 | 이유 |
|---|---|
| "토큰" / "크레딧" / "분석 횟수" | 실제 계약과 충돌(§3.3) |
| 플랜 무관 "광고를 봐야 해요" | 유료는 광고 없이 진행됨(§24.2) |
| 강제되지 않는 혜택 광고 | Q6 LOCKED |

| "다시 시도해 주세요"만 있는 오류 | §15.3 |

# 32. Migration strategy from current UI

## 32.1 원칙

1. **구조 → 상태 → 표면 순서로 옮긴다.** 색·타이포부터 바꾸면 구조 문제가 예쁜 채로 남는다.
2. **각 단계는 독립적으로 출시 가능해야 한다.** 전체를 멈춰 세우지 않는다.
3. **회귀 검증 가능한 단위로 자른다.** 한 PR에서 구조와 표면을 함께 바꾸지 않는다.

## 32.2 재사용 / 교체 / 폐기

### ✅ 그대로 유지 (건드리지 않는다)

- 페이월 하단 법적 고지·복원·관리 (심사 요건 충족)

## 32.3 위험 구간과 완화

| 위험 | 완화 |
|---|---|
| ViewModel 소유권 이동이 광범위한 참조를 건드림 | 참조 경로만 바뀌고 로직은 불변. **1개 PR로 묶고 회귀 테스트 집중** |
| 타이포 교체가 전 화면 레이아웃에 영향 | 기본 Dynamic Type 크기에서 **시각적 회귀 0**(§6.3 매핑표). 스크린샷 diff로 검증 |
| 모의고사 stage 라우팅 재작성 | 서버 변경 없이 클라이언트만. **stage별 수동 검증 시나리오 9개** 작성 |
| A/B/C 버킷 도입 | 임계값 미정 상태에서는 **A 버킷만 활성화**하고 B/C는 플래그로 비활성 출시 가능 |
| 광고 배치 변경 | 수익 영향 모니터링 구간 필요. 배너 제거는 데일리 한 화면에 국한 |

## 32.4 하지 않는 것

- 빅뱅 리라이트
- 백엔드와 동시 변경 (backend 작업은 §33 P5로 분리)
- 상품·가격·광고 정책 변경 (LOCKED)
- 존재하지 않는 기능 추가

# 34. 플래너 (Calendar Foundation · G2 / 적응형 플래너 · G3 / 플랜 게이팅 · G4 / IA · P2 / 하루 상세 · P3 / 학습 알림 유료화 · P4)

제품 정의 · 예측 상수 · 완료 정의는 PRODUCT.md §16, 적응형 계획 규칙은 §17,
화면 구성과 일요일 시작은 §21이 진실이다. 여기서는 화면과 계층만 다룬다.
사용자에게 보이는 이름은 **플래너**이고, 내부 타입 이름(`StudyCalendar…`)은 그대로다.

## 34.1 위계 — 오늘이 먼저다

한 페이지에 전부 쌓지 않는다(P2). 탭 뿌리는 **플래너 홈**이고, 월간 격자와 설정은
각각 **전체 캘린더**·**플래너 설정**으로 내려간다. 탭이 이미 가진 `NavigationStack`을
쓰고(`PlannerRoute`), 전역 내비게이션 구조는 바꾸지 않는다.

플래너 홈, 위에서부터:

1. **문맥 한 줄** — "목표 IH · 시험 D-24". 시험일이 없으면 "목표 IH"까지만.
   지어내지 않는다. 도구 막대 오른쪽에 플래너 설정 버튼(아이콘 + 접근성 레이블).
2. **오늘의 학습** — 첫 화면의 주인공. "1 / 2세트" + 주 액션
   `학습 시작하기`(오늘 한 세트도 안 했을 때) / `학습 이어하기`(하다 만 상태).
   데일리 탭으로 이동한다 — 플래너는 학습 화면을 따로 만들지 않는다.
   완료면 "오늘 학습 완료", 휴식일이면 "오늘은 쉬는 날이에요",
   계획을 다 끝냈으면 "계획한 학습을 모두 완료했어요".
3. **주간 스트립** — 일~토 7칸. 사용자 지역 설정과 무관하게 **일요일 시작**
   (월간 격자·공부 요일 선택과 순서를 맞춘다).
4. **진행** — "이번 주 3 / 5일 완료" · "연속 학습 🔥 3일" ·
   "남은 권장 학습 12세트 · 9월 14일 완료 예상".
5. **계획 위험 안내** — 압축·시간 부족·시험 후 완료. 권하는 행동은 설정 수정뿐이다.
6. **`전체 캘린더 보기`** — 월간 보기로 가는 한 줄.
7. **면책 문구** — "…실제 OPIc 등급 달성을 보장하지 않아요."
   시험일과 완료 예상일은 **다른 줄**에 둔다. 섞으면 취득일 약속으로 읽힌다.

전체 캘린더: 월 이동 · 일~토 머리글 · `LazyVGrid` 7열 · 범례 · 이번 달 요약 한 줄.
**외부 캘린더 라이브러리 없음.** 날짜 칸은 `NavigationLink(value: .dayDetail("yyyy-MM-dd"))`라
같은 스택에서 **하루 상세**(§34.11)로 밀린다.

플래너 설정: 목표 등급 · 시험일 · 공부 요일 · 학습 강도 · 선호 공부 시간 ·
학습 알림(§34.9) · 잠긴 자동화 기능(§34.8) · 저장. 저장 성공하면 홈으로 돌아온다.

일요일 시작은 **표시 순서일 뿐**이다. 머리글만 돌리고 격자 오프셋을 두면 어긋나므로
둘 다 `StudyWeekday.displayColumn`(일=0 … 토=6) 하나를 쓴다. 저장·전송 값은 ISO
(월=1 … 일=7) 그대로다.

## 34.2 상태 표기

`StudyDayState`는 색이 아니라 **SF Symbol + 문구**로 구분한다(§9 색 단독 금지):
휴식 `moon.zzz` · 예정 `circle.dotted` · 일부 완료 `circle.lefthalf.filled` ·
완료 `checkmark.circle.fill` · 놓침 `exclamationmark.circle`.
월간 보기 하단에 같은 기호로 범례를 둔다.

## 34.3 접근성

- 날짜 칸은 `accessibilityElement(children: .ignore)` + 한 문장 레이블:
  "8월 14일 금요일, 완료, 2 / 2 세트". 요일 약자("금")는 VoiceOver가 읽지 못하므로
  `StudyWeekday.accessibilityLabel`("금요일")을 쓴다.
- 요일 칩·강도 선택은 `.isSelected` 트레이트 + `minimumTouchTarget()`(44×44).
- 요일 칩은 고정 폭 대신 균등 분할이라 AX 크기와 작은 아이폰에서도 7칸이 유지된다.
- 폰트는 전부 `AppTypography`(Dynamic Type), 커스텀 폰트 없음.

## 34.4 빈 상태 / 오류

| 상황 | 화면 |
|---|---|
| 계획 미설정 | 5단계 온보딩(§PRODUCT 16.2) |
| 불러오는 중 | `AppLoadingIndicator` + "학습 계획을 불러오고 있어요." |
| 서버 실패 + 로컬 사본 있음 | 대시보드 + "오프라인이라 저장된 학습 계획을 보여주고 있어요." |
| 서버 실패 + 사본 없음 | 플래너 탭 안에서만 재시도 버튼. **다른 탭은 영향 없음** |
| 목표 등급 없음 | 기본값 IM2로 표시하고 1단계에서 기존 난이도 재선택 경로 제공 |

오프라인 동기화 엔진은 만들지 않는다. 마지막 성공 설정 하나만 캐시한다.

## 34.5 계층 — 날짜 계산은 View에 없다 (G3)

```
StudyPlanEstimator      권장 총 학습량 · 기본 하루 학습량 · 하루 상한 (순수 함수 · 상수 한 곳)
AdaptiveStudyPlanner    남은 학습량 → 모드 판정 → 날짜별 분배 (결정론적 · 저장 없음)
StudySchedule           날짜 → 배정 학습량. 과거는 고정 기록, 오늘·미래는 계획
StudyCalendarEngine     배정량 + 완료량 → 하루 상태 · 스트릭 · 주간 요약
StudyCalendarSnapshot   화면이 한 번에 쓰는 파생값 묶음 (매번 계산 · 저장 안 함)
StudyCalendarViewModel  I/O만 — 서버 설정 로드/저장, 배정량 고정(freeze)
StudyCalendarScreen     렌더링만 — 날짜 계산 · 매직 넘버 없음
```

`Calendar.current`를 캘린더 계산에 쓰지 않는다. 전부 `settings.calendar`
(그레고리력 + 저장된 타임존)로 통일한다(PRODUCT §17.9). 유일한 예외는 최근 분석
결과의 "나이(일수)" 판정으로, 로컬 날짜 키가 아니라 절대 시각 간 경과라서 그대로 둔다.

## 34.6 배정량 고정 (`StudyDayPlanRecord`)

지난 날의 목표가 현재 설정으로 다시 계산되던 G2 결함을 막는 최소 저장소다.
로컬 SwiftData 전용이며 서버로 보내지 않는다(크로스 디바이스는 범위 밖).

| 필드 | 의미 |
|---|---|
| `localDate` | "yyyy-MM-dd" · **유일 키** · 계획 타임존 기준 |
| `targetSets` | 그날 배정된 학습량. 휴식일(0)은 저장하지 않는다 |
| `createdAt` | 고정 시각 |

대시보드가 나타날 때 `freezeStudyDayPlans`가 오늘까지의 배정량을 채운다. **지난
날짜는 이미 기록이 있으면 절대 덮어쓰지 않고**, 오늘만 현재 계획에 맞춰 갱신한다.
완료 수는 여기에 복제하지 않는다(완료의 진실은 `StudySetCompletionRecord`뿐).
보관은 1년치.

### 기록이 없는 지난 날 (materialize + seal)

기록은 캘린더를 열 때만 생기므로 며칠 열지 않으면 구멍이 생긴다. 그 구멍을 두 곳에서 메운다.

| 시점 | 하는 일 | 근거 |
|---|---|---|
| 화면 계산 (`StudySchedule.init`) | `AdaptiveStudyPlanner.historicalTargets`로 계획 시작일~오늘의 학습일 배정량을 되살리고, 고정 기록이 있으면 **기록이 이긴다** | 저장 여부와 무관하게 지난 학습일이 휴식으로 보이지 않는다 |
| 설정 저장 직전 (`StudyCalendarViewModel.sealHistory`) | **바뀌기 전 설정**으로 오늘까지를 고정한다 | 설정 변경 뒤에 되살리면 과거가 새 설정으로 왜곡된다 |

되살리기와 고정은 같은 함수(`historicalTargets`)를 쓴다 — 화면에 보인 값이 그대로
저장된다. 되살리기는 계획 시작일 이후의 **학습일**에만 적용되므로 휴식일은 휴식으로
남고, 앱 시작 시 네트워크 작업이나 별도 일정 DB·서버 동기화는 만들지 않는다.

## 34.7 적응형 상태 문구

| 모드 | 화면 |
|---|---|
| 평소 | "남은 권장 학습 14세트" + "8월 21일 완료 예상 · 약 7일" |
| 압축 | 위 + "시험일까지 남은 기간을 반영해 학습량을 조정했어요." |
| 부족 | `AppPalette.danger`로 "현재 설정으로는 시험 전 권장 학습량을 모두 완료하기 어려워요." + "남은 권장 학습 N세트 · 현재 일정에서 시험 전 최대 M세트 가능" + `학습 설정 수정` |
| 완료 | "권장 학습 계획을 완료했어요." · 오늘 카드에 의무 학습을 만들지 않는다 |

오늘 카드는 배정량을 넘겨 학습하면 "오늘 계획보다 N세트 더 학습했어요. 남은 일정에
반영했어요."를 덧붙인다. **부족 상태에서도 페이월을 열지 않고 상위 플랜을 권하지
않는다**(§34.8). 주간·월간 보기에는 숫자를 더 얹지 않는다 — 위계는 여전히 오늘이 먼저다.

## 34.8 잠긴 캘린더 기능 (G4 · P4)

캘린더는 **전 플랜이 들어온다.** 잠기는 것은 자동화와 학습 알림(P4)뿐이다(PRODUCT §18).
잠금 판정의 진실은 언제나 `CalendarFeaturePolicy` 하나이며, 뷰·서비스에 `plan != .free`
같은 검사를 흩뿌리지 않는다.

**배치.** 잠긴 기능은 "학습 플랜 기능" 카드 **한 곳**에만 모은다. P2부터 그 자리는
**플래너 설정**(공부 시간·알림 아래)이다 — 홈은 "오늘 뭘 할까"에 답하는 자리라
기능 설명을 두지 않는다. 달력 셀·오늘 카드·상태 문구에는 자물쇠를 뿌리지 않는다.
잠긴 게 없으면 카드가 없다.

**행 구성.** `제목` / `한 줄 설명` / `"베이직부터"` 요구 플랜 배지. 행 전체가 버튼이며
`.minimumTouchTarget()`을 지킨다.

| 기능 | 제목 | 요구 플랜 |
|---|---|---|
| `auto_replan` | 자동 일정 재조정 | 베이직 |
| `evaluation_adaptive` | 최근 평가를 반영한 학습 계획 | 플러스 |
| `exam_backplan` | 시험일까지 역산한 일정 | 플러스 |
| `study_reminder` | 학습 알림 | 베이직 |

`study_reminder`(P4)는 같은 잠금 행 컴포넌트를 쓰지만 이 카드에는 **넣지 않는다.**
자기 자리(알림 칸, §34.9)가 이미 있어서 한 화면에 두 번 보이기 때문이다. 목록은
`CalendarLockedFeature.automationCases`로 만들고, 알림은 `allCases`에만 있다.

**페이월은 사용자가 연다.** 캘린더 진입 · 완료 예상 부족 · 학습 누락 · 시험일 임박 —
어느 것도 자동으로 페이월을 열지 않는다. 잠긴 행을 **누른 순간에만** 열린다
(`PaywallSource.calendarLocked`). 부족(`insufficientTime`) 상태의 CTA는 여전히
`학습 설정 수정` 하나뿐이고 업셀이 아니다.

**접근성.** 행 하나가 한 문장으로 읽힌다 — "자동 일정 재조정, 잠김, 베이직부터 이용 가능".
자물쇠는 아이콘만으로 의미를 전달하지 않고 텍스트 배지를 함께 쓴다.

## 34.9 학습 알림 (G5 · 유료화 P4)

**배치.** 캘린더 안에서 알림 이야기를 하는 곳은 `StudyReminderCard` **한 칸**뿐이다(주간 요약과
잠긴 기능 카드 사이 → P2부터 **플래너 설정**의 공부 시간 피커 바로 아래. 같은 화면에 시간
피커가 있으므로 카드의 `시간 변경` 버튼은 감춘다). 오늘 카드·달력 셀·월간 보기에 알림
배지를 뿌리지 않는다.

**P4부터 유료 기능이다.** 그 한 칸이 플랜에 따라 두 모습 중 하나가 된다 — 유료는 지금까지의
`StudyReminderCard`, 무료는 같은 자리의 **잠긴 행**(자물쇠 + "학습 알림" + "베이직부터 이용 가능").
무료에게 **숨기지 않는다**: 없는 것처럼 보이면 팔 수도 없고, 잠긴 줄 모르면 왜 안 오는지도 모른다.
분기 기준은 `viewModel.canUseStudyReminder` 하나뿐이고 뷰가 플랜을 직접 보지 않는다(§34.8과 같은
`CalendarFeaturePolicy`). 무료 카드는 "매일 21:00" 같은 **켜져 있다는 뜻의 문구를 절대 쓰지 않는다.**

**권한 흐름.** 시스템 권한 창은 오직 카드 안 CTA → 앱 설명 다이얼로그 → `알림 켜기`에서만
뜬다. 화면 진입·`.task`·`.onAppear`·구매 완료·오류 복구 어디에도 권한 요청이 없다.
무료 상태에서는 CTA 자체가 없으므로 권한 요청 경로도 없다. 잠긴 행을 누르면
`AppTelemetry.calendarFeatureLockedTap` 한 줄을 남기고 기존 페이월(`PaywallSource.calendarLocked`)이
열린다 — 알림 전용 페이월을 새로 만들지 않았다.

| 상태 (베이직 이상) | 카드 |
|---|---|
| 꺼짐 / 미결정 | "설정한 공부 시간에 오늘 계획을 한 번 알려드려요." + `학습 알림 켜기` |
| 켜짐 | `bell.fill` "매일 21:00 · 학습일에만" + `시간 변경` · `알림 끄기` |
| 거부 | `bell.slash.fill` "알림이 꺼져 있어요." + `설정에서 알림 허용` · `알림 끄기` |

`시간 변경`은 새 시각 필드를 만들지 않고 기존 학습 설정 수정(`StudyPlanEditView`)으로 보낸다 —
알림 시각의 진실은 `preferredStudyTime` 하나다.

**계층.** `UNUserNotificationCenter`를 만지는 곳은 `StudyReminderService` 하나다. SwiftUI 뷰에
알림 API 호출을 흩지 않는다. 센터는 `UserNotificationCenterProtocol`로 주입되어 테스트가
실제 권한 창을 절대 띄우지 않는다. 예약 목록 계산은 순수 함수(`StudyReminderPlanner`)이고,
일정 진실은 캘린더와 같은 `AdaptiveStudyPlan.upcomingDays`다(§34.5와 같은 원칙).

**자격 강제도 한 곳이다.** `reconcile(_:isEligible:)`가 예약을 맞추기 **전에** 자격을 본다.
자격이 없으면 우리 접두사(`dailyopic.study-reminder.*`)의 대기 알림만 지우고 로컬 의도를 끈다.
OS 권한은 건드리지 않고 `requestAuthorization`도 부르지 않는다. 이 검사가 "일정을 아직 모른다"
(`nil`) 분기보다 **앞에** 있어서, 강등된 사용자는 계획이 로드되기 전인 앱 시작 직후에도 정리된다.
서비스는 플랜을 모른다 — 자격은 `StudyCalendarViewModel.reconcileStudyReminders()`가
`CalendarFeaturePolicy`에서 읽어 넘긴다. 취소 코드를 다섯 진입점에 복사하지 않는 이유다.

**접근성.** 상태를 색으로만 구분하지 않는다(아이콘 + 문구). 켜짐 카드는 "학습 알림 켜짐,
학습일 오후 9:00"으로 한 문장으로 읽힌다. 모든 버튼은 `.minimumTouchTarget()`과 기존
`AppTypography`·`AppPalette` 토큰만 쓰고 커스텀 폰트를 쓰지 않는다. 본문은 Dynamic Type에서
잘리지 않도록 `.fixedSize(horizontal: false, vertical: true)`.

## 34.10 App Store 평점 요청 (G6)

**화면에 추가되는 것은 없다.** 별 UI·만족도 질문·리뷰 모달·설정의 "평가하기" 항목을 만들지
않는다. 뜨는 것은 Apple의 네이티브 창뿐이고, 그 창을 띄울지는 Apple이 정한다. 창이 뜨지
않아도 결과 화면은 평소와 똑같다 — 리뷰가 화면 전환이나 결과 표시를 막지 않는다.

**호출 지점.** `PracticeScreen`에서 **방금 성공한 분석 결과가 화면에 올라온 뒤** 한 번만
`@Environment(\.requestReview)`를 호출한다. `PracticeViewModel.freshResultToken`은 분석
성공 경로에서만 켜지고 화면이 소비하면 비워진다. 그래서 이전 문항 결과를 다시 보거나
(`savedResult`), 기록 화면(`HistoryDetailView`)에서 같은 `PracticeResultView`를 다시
그려도 요청이 나가지 않는다. `onAppear` 호출 횟수에 기대지 않고, 시도 시각을 남기는
30일 쿨다운이 한 번 더 막는다.

**계층.**

| 층 | 역할 |
|---|---|
| `AppReviewEligibility` | 순수 판단 — 순간·배포 경로·성공 기록·쿨다운만 본다 |
| `AppReviewCoordinator` | 시도 기록(쿨다운 타임스탬프) · 계측 |
| 뷰 | 네이티브 `RequestReviewAction` 호출 한 줄 |

자격 계산은 등급을 **입력으로 받지 않는다**(PRODUCT §20.3). 근거는 캘린더와 같은
`StudySetCompletionRecord`이고 리뷰 전용 카운터를 새로 만들지 않는다. `AppDistribution`은
DEBUG 빌드와 영수증 파일명(`sandboxReceipt` = TestFlight/샌드박스)으로 판별하며,
TestFlight와 판별 불가(unknown)는 요청하지 않는다. 테스트는 배포 경로와 요청 동작을 모두
주입해 **실제 네이티브 창을 띄우지 않는다**.

## 34.11 하루 상세 · 개인 일정 · 메모 (P3)

제품 규칙은 PRODUCT.md §22가 진실이다. 여기서는 화면과 계층만 다룬다.

**내비게이션.** 시트를 겹치지 않는다. 전체 캘린더의 날짜 칸이
`PlannerRoute.dayDetail(String)`을 밀어 탭이 이미 가진 `NavigationStack` 안에서 열린다.
경로 값은 `Date`가 아니라 **"yyyy-MM-dd" 문자열**이다 — `Date`를 실으면 기기 타임존이
바뀔 때 다른 날이 열린다. 유일한 시트는 하루 상세 안의 일정 편집기이고,
페이월 시트는 플래너 설정 쪽 가지에 있어 서로 만나지 않는다.

제목은 `"8월 20일 목요일"`을 직접 조립한다(`dateComponents` + `StudyWeekday.accessibilityLabel`).
로케일 포맷터를 쓰면 계획 타임존과 기기 타임존이 어긋날 때 하루가 밀린다.

**구성.** 위에서부터 ① 학습 기록 카드(읽기 전용) ② 개인 일정 ③ 메모.

**학습 상태는 두 번 계산하지 않는다.** `StudyCalendarScreen`이 격자와 **같은**
`StudyCalendarEngine.day(...)` 호출로 `StudyDay`를 만들어 넘기고, 화면은
`PlannerDayStudyStatus.make(day:isStudyWeekday:)`로 문구·기호만 고른다. 지난 날짜의
배정량은 `snapshot.schedule`에 이미 합쳐진 `historicalTargets`에서 나오므로
강도를 올려도 어제의 판정이 바뀌지 않는다(§34.6과 같은 불변식). 배정량이 0이면
`Daily 0 / 0`처럼 없는 목표를 지어내지 않고 세트 줄을 접는다.

**계층.**

| 층 | 역할 |
|---|---|
| `PlannerEventRecord` · `PlannerDayNoteRecord` | 로컬 SwiftData 모델. 키는 `localDate` 문자열, 시각은 `timeMinutes`(자정 이후 분) |
| `PersistenceService` | 쓰기 전담 — 저장·수정·삭제, 제목 트림/빈 값 거부, 공백 메모 삭제 |
| `PlannerDayDetailView` · `PlannerFullCalendarView` | `@Query`로 읽기만 한다(기존 `StudyCalendarScreen` 관례 그대로) |

`PersistenceService`는 `MainTabView` → `StudyCalendarScreen` 인자 하나로 내려온다.
새 리포지토리 추상화를 만들지 않는다.

`DailyOPIcApp`의 `Schema`에 두 모델을 **추가만** 한다. 기존 모델을 하나라도 빠뜨리면
그 모델의 저장 데이터가 통째로 사라진다.

**메모 저장 시점.** 타이핑마다 저장하지 않는다. 내용이 바뀌었을 때만 나타나는
`메모 저장` 버튼 + 화면을 벗어날 때(`onDisappear`) 한 번, 두 경로뿐이다.

**개인 일정에는 알림이 없다.** P4에서 알림을 유료화하면서도 알림 상품은 여전히
학습 알림(§34.9) 하나다. 일정 편집기에 알림 스위치를 붙이지 않았고, 하루 상세·일정·메모는
플랜을 보지 않는다(전 플랜 동일 · 로컬 전용).

**격자 표시와 접근성.** 학습 상태 기호(16pt) 아래에 개인 일정 5pt 점,
메모 7pt `text.alignleft`를 얹고 둘 다 `accessibilityHidden`이다. 대신 칸의 한 문장
레이블 끝에 "개인 일정 있음" · "메모 있음"을 덧붙인다(색·모양 단독 금지, §9).
일정 행은 "시간 없음, 스터디 모임"처럼 시각을 먼저 읽는다.
